# 02｜用户流程与状态机

## 1. 领域对象

- `Project`：长期保留的业务工作区。
- `DataAsset`：用户导入的原始文件及其文件级元数据。
- `DatasetVersion`：关联、清洗或 Notebook 输出形成的不可变数据快照。
- `JoinPlan`：关联步骤、键、基数假设和验证结果。
- `TargetTask`：某个数据版本上的单一 Y 建模任务。
- `Run`：一次可复现执行；固定 Y、数据版本、模式和方案。
- `Checkpoint` / `Decision`：暂停恢复状态和用户确认。
- `ReviewRecord`：Reviewer 每轮意见、证据与结论。
- `ModelVersion` / `Artifact`：冻结模型与报告、Notebook、模型包等产物。
- `Conversation`：项目级多轮对话与反馈。

## 2. 主流程

1. 创建项目；机构、产品、说明均为可选，不阻碍创建。
2. 导入本地数据和可选数据字典；Excel 多 Sheet 先选 Sheet。
3. 直接物化单表，或按四级关联路径生成数据版本。
4. Agent 识别所有候选 Y；用户创建一个或多个 Y 任务。
5. Run 依次执行 11 个阶段：Y、诊断、清洗、切分、筛选、分箱、模型方案、代码与质检、训练与校准、报告与模型包、完成。
6. 通过报告页上传新样本批量评分。

## 3. Run 状态

- `queued`：等待本地执行资源。
- `running`：当前节点正在执行。
- `awaiting_decision`：LangGraph 已暂停并持久化 checkpoint。
- `succeeded`：产物生成完成；质量结论可能是通过或条件通过。
- `failed`：执行错误，保留错误码、最后事件和重试入口。
- `blocked`：用户拒绝或安全/合同门禁阻止继续。

关闭页面不取消 Run。应用重启后从 SQLite checkpoint 恢复；不得重新执行已经确认且有完整证据的上游节点。

## 4. 半信任确认点

- 确认 Y、0/1 语义和被排除的 `-1/空值`。
- 确认清洗动作。
- 确认 Train/Test/OOT、时间字段、客户主键和比例。
- 确认最终变量及带理由的普通变量恢复。
- 确认自动/人工分箱版本。
- 确认候选模型和评分参数。

每张确认卡必须先显示 Reviewer 状态、业务摘要、可修改项和明确的批准/停止动作。点赞只用于反馈，不等于批准。

## 5. 失效传播

- 数据或关联变化：Y、诊断、切分、筛选、分箱、模型、报告、评分全部失效。
- Y 有效样本变化：该 Y 的切分及所有下游失效，不影响其他 Y。
- 切分变化：筛选、分箱、训练、审核、报告失效。
- 恢复/排除变量变化：分箱、训练、审核、报告失效。
- 人工分箱变化：训练、审核、报告失效并生成新分箱版本。
- 模型/评分参数变化：训练、审核、报告和模型包失效。

失效只创建新版本或新 Run；不覆盖旧证据。

## 6. 多 Y 队列

同一项目的 Y 任务按 `queue_position` 顺序执行。每个任务持有独立状态。某个任务失败、被拒绝或资源延期时，调度器记录原因并允许后续任务继续；不得把一个 Y 的样本、IV 或分箱复用于另一个 Y。

## 7. 错误与恢复

- 用户可修复：Sheet 未选、关联键不完整、切分字段无效、恢复理由不足。
- 自动降级：资源不足时减少挑战模型、降低并发或延后执行，并显示原因。
- 安全阻断：PII/原始表外发、密钥泄露、路径越界、模型包校验失败。
- 业务阻断：单一 Y 类别、关联膨胀、客户跨集合、OOT 被用于选择。

时间 OOT 必须记录明确 cutoff，并验证 `max(dev_time) < min(oot_time)`。同时要求客户互斥时，跨 cutoff 客户和无效时间样本不被暗中塞入任一集合，而是进入带原因、行数和索引哈希的排除证据。

任何失败必须保留机器可读错误码；不得静默删样本或自动改变 Y。
