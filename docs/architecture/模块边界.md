# 模块边界

本项目把“Agent 决策”“确定性建模”“本地基础设施”视为不同职责。目录名称不是装饰，依赖方向由自动化测试约束。

## 依赖方向

```text
desktop / api / evaluation / bootstrap / packaging
            |
       orchestration
       /     |      \
  services  agents  governance
       \      |      /
          workers / providers
                 |
            domain / core
```

- `domain`：纯业务规则与稳定契约，不依赖框架、数据库或第三方模型。
- `core`：路径、配置、数据库、安全和错误等本地基础设施底座。
- `workers`：数据、统计、建模、报告和评分等确定性函数，不调用 Agent、API 或应用服务。
- `providers`：唯一 LLM 网络出口，只负责协议、配置、密钥和连接诊断。
- `agents`：提示词、SafeEvidence 和独立 Reviewer；不拥有 Run 持久化。
- `services`：项目、数据、产物、会话和建模阶段用例，可组合 Agent 与 Worker。
- `governance`：运行清单、Trace 和可审计证据。
- `orchestration`：LangGraph、Checkpoint、HITL、子进程与终态管理。
- `desktop`：Tauri 窗口、启动认证与冻结后端生命周期；不复制前端、Agent、Worker 或建模业务逻辑。
  - `backend.rs` 只保留监督状态机；`backend/protocol.rs`、`process.rs`、`window.rs`、`logging.rs` 分别拥有本机协议、进程树、窗口与日志边界。
- `core/desktop_auth`：只管理桌面启动凭据、一次性 WebView bootstrap 和 HttpOnly 业务会话；`main` 只负责组装路由与生命周期回调。
- `frontend/shared/lib/uiPreferences`：仅保存非敏感界面偏好，并屏蔽桌面随机端口造成的 Web Storage origin 差异；业务 feature 不直接选择持久化介质。
- `api`、`evaluation`、`bootstrap`、`packaging`：最外层接口、评测适配、组合根与离线包自检；它们只组合内部能力，不承载业务算法。

## 不变量

1. 原始数据不进入 Provider；Provider 只接受 SafeEvidence。
2. Worker 不伪装成 Agent，也不依赖 Agent 的实现状态。
3. Reviewer 终态判断属于领域规则，报告与编排共用同一规则。
4. 所有算法通过模型适配器注册，不在 Pipeline 中直接判断第三方库细节。
5. 模型和 Provider 的可用状态必须可诊断，缺失时不得静默降级。
6. API、数据库记录、历史 Run 和模型包升级时保持兼容。

`tests/test_architecture_boundaries.py` 会在 CI 中拒绝反向依赖。确需改变边界时，必须先修改本文件和测试，再迁移调用方，不能增加临时例外掩盖循环依赖。
