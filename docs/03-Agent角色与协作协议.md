# 03｜Agent 角色与协作协议

## 1. 架构结论

V1 使用 LangGraph 作为有状态编排层；不引入完整 LangChain 全家桶，也不采用 Pi Agent 作为主运行时。Agent 是有边界的角色，不是任意自治进程。本地 Worker 是工具，不伪装成 Agent。

## 2. 角色

### 主 Agent

读取聚合项目状态，提出下一步计划，调用强类型工具，生成面向用户的业务说明，并把 Reviewer 反馈转换为受控修订任务。它不能直接读取云端未授权数据，也不能跳过安全阻断。

### Reviewer Agent

使用与主 Agent 隔离的上下文，审核：

- 数据/切分/筛选/模型计划；
- 本地生成的可复现代码；
- 模型执行范围、指标、候选失败隔离和 OOT 证据；
- 结构化报告的一致性和治理结论。

Reviewer 输出结构化 `status`、`issues`、`evidence`。没有 Provider 时，确定性审核仍保留，并明确记录 `provider=disabled`。

### LLM 与 Worker 边界

LLM 可以推荐模型、解释风险、生成或修订模板代码；AUC、KS、IV、WOE、PSI、Lift、分箱、训练、序列化和哈希必须由本地确定性工具完成。

## 3. Reviewer 循环

1. 主 Agent 生成冻结方案或代码。
2. Reviewer 在独立上下文读取 SafeEvidence、代码摘要和执行证据。
3. 若 `revise`，将结构化意见反馈主 Agent。
4. 主 Agent 仅在允许的模板/参数范围内修复。
5. 最多三轮；仍有问题时只允许安全核心模型或确定性模板降级。
6. 阻断问题仍存在时 Run 失败，不能伪装成通过。

候选模型单独失败不会让整个 Run 失败，但必须在报告记录；没有成功 Champion、OOT 参与选择、指标缺失、范围不合规等属于阻断。

## 4. Human in the Loop

半信任模式中，Reviewer 完成预审后才向用户展示确认卡。用户确认业务选择，不需要阅读长代码。完全信任模式只自动批准业务确认点，不自动放行安全、数据合同或 Reviewer 阻断。

## 5. 多轮对话

对话持久化到项目，可关联当前 Run。Agent 回复可以解释当前节点、指标与下一步，但不能输出隐藏思维链。自由文本在外发前必须通过意图约束和 DLP；疑似凭据、个人标识或原始表格内容留在本地。

## 6. 工具协议

所有工具通过强类型 Tool Registry 注册：名称、输入模型、输出模型、权限、是否可外发、证据字段和错误码均固定。V1 的 MCP 边界为关闭状态；未来适配器也必须映射到相同合约，不能绕过 Registry 发现任意工具。

## 7. 可观察输出

每个 Run 事件至少包含：单调递增序号、阶段、节点、Agent、工具、状态、摘要、UTC 时间、证据引用。外部 Provider 请求只记录模型、用途、SafeEvidence 哈希、状态和用量，不记录密钥或原始数据。
