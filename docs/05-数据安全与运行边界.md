# 05｜数据安全与运行边界

- 文档版本：v1.0
- 日期：2026-08-20
- 目标：定义本地数据、外部 LLM、凭据、工具、代码执行和审计边界

## 1. 核心承诺

原始数据绝对不上传云端。产品只允许向已配置的外部 LLM API 发送经过本地脱敏、聚合、阈值抑制和审计的安全证据。

这一承诺要求由代码和网络边界实现，不能只依赖 Prompt 告诉 Agent“不要上传”。

## 2. 数据分类

| 等级 | 示例 | 是否可发送外部 LLM |
|---|---|---:|
| D0 原始敏感数据 | 原始行、姓名、手机号、身份证、卡号、地址 | 否 |
| D1 客户级派生数据 | 单客户特征、逐行预测、SHAP、拒绝原因 | 否 |
| D2 文件与模型 | CSV/XLSX 原文件、模型二进制、完整代码运行目录 | 否 |
| D3 受控聚合证据 | 行列数、缺失率、分箱统计、匿名字段角色 | 条件允许 |
| D4 产品元数据 | 节点名、错误码、工具状态、版本 | 允许，仍需审计 |

字段名本身可能包含敏感含义。Provider Gateway 应支持字段别名、敏感词扫描和本地映射。

## 3. 本地与云端边界

### 必须留在本地

- 原始文件和解析后的 DataFrame；
- 客户级记录与标识符；
- 清洗后的逐行数据；
- 训练、验证、OOT 样本成员；
- 模型文件、预处理器、评分结果；
- 完整运行目录和密钥；
- 未经过安全策略处理的日志。

### 可以在策略允许后发送

- 字段别名与类型；
- 行数、列数、缺失率、唯一值数；
- 达到最小样本量的分箱/分组统计；
- Y 的聚合分布；
- 不含客户级信息的模型指标；
- 代码文本和结构化方案，但不得包含数据样本或秘密；离开本机的代码、方案和字段字典必须使用别名，不得出现原始列名；
- 工具状态、错误码和产物哈希。

## 4. SafeEvidence 构建

每次 LLM 请求必须先构建 `SafeEvidenceBundle`：

```json
{
  "schema_version": "risk-safe-evidence/v1",
  "project_id": "proj_xxx",
  "dataset_hash": "sha256:...",
  "field_aliases": {
    "f_001": "numeric_risk_history"
  },
  "aggregates": {},
  "suppression": {
    "min_group_size": 50,
    "suppressed_groups": 7
  },
  "policy_version": "evidence-policy/v1",
  "bundle_hash": "sha256:..."
}
```

处理步骤：

1. 移除原始行和客户级值；
2. 按保守规则、敏感词名单和项目配置识别疑似直接/间接标识符；不承诺穷尽识别，无法判断时默认不外发；
3. 把字段名、代码引用和方案引用统一替换为别名与角色，并仅在本地执行入口映射回原名；
4. 聚合连续变量并限制精度；
5. 隐藏小样本分组；
6. 限制返回行数和唯一值列表；
7. DLP 扫描；项目对话默认不外发原句，只允许本地识别出的结构化意图和 SafeEvidence；疑似凭据、邮箱、手机号/卡号或无法归类的自由文本回到本地确定性回复；
8. 记录策略与内容哈希；
9. 仅通过 Provider Gateway 发送。

安全证据阈值必须可配置并版本化。默认值不是合规结论。

## 5. 外部 LLM Provider Gateway

- 支持两种显式线协议：OpenAI Chat Completions 与 Anthropic Messages；业务层不绑定单一供应商。
- V0.1 提供 DeepSeek、Kimi 开放平台、Kimi Code、OpenAI、Anthropic 预置。DeepSeek/Kimi Code 可分别选择 OpenAI 或 Anthropic 兼容入口；Kimi 开放平台预置走 OpenAI 兼容入口；也可填自定义 Provider。
- DeepSeek、Kimi Code 的预置 Base URL 和模型只是可编辑默认值，供应商账户的可用模型、额度和地区可用性仍以其控制台为准。
- 主 Agent 与 Reviewer 可分别配置模型；
- Gateway 统一执行超时、重试、限流、Schema 校验和日志脱敏；
- 支持企业 HTTP/HTTPS 代理、CA 证书路径和连通性自检；
- LLM 不可用时，确定性 Worker 流程仍可继续，Agent 节点明确标记“LLM 不可用”，不得伪造 Agent 结论；
- 单次 Run 与单月 token/费用预算必须可配置，触顶时停止或降级为确定性流程，并写入 Trace；
- 请求只接收 `SafeEvidenceBundle`、方案和代码等允许内容；
- API 响应视为不可信输入，必须经过 Schema 与领域校验；
- 不把供应商“零留存”宣传当作本地数据安全替代品；
- 企业部署前单独确认供应商合同、地区、留存和训练条款。

## 6. API Key 与凭据

- API Key 不写入 `.env.example` 的真实值、不写数据库、不写项目文件、不进入 Git；
- 桌面版使用 macOS Keychain 或 Windows Credential Manager；
- 浏览器前端永远看不到完整 Key；
- 后端按需读取，错误日志不得包含 Key、Authorization Header 或完整请求；
- 支持用户删除、替换和测试凭据；连通性测试可以直接使用设置页当前尚未保存的 Key，但不会把它写入配置文件。
- 不把 LLM Key 传给 Worker 或生成代码进程。

## 7. Worker 权限

- 默认无网络；
- 只读取经验证的本地数据引用；
- 只写当前项目受控产物与临时目录；
- 不接受用户提供的任意绝对路径；
- 不继承不必要的环境变量和凭据；
- 目标规模的训练、画像和生成代码相关任务由父进程控制资源、超时和取消并进入受控子进程；当前 V0.1 对已通过导入前资源预估的默认规模画像/EDA 使用受边界保护的进程内调用，训练仍进入受控子进程；
- 工具白名单和参数 Schema 在服务端校验。

MCP 不是自动获得信任的工具来源。未来接入 MCP 时必须逐服务器和逐工具授权，V1 不允许 Agent 自由发现并调用任意 MCP。

## 8. 生成代码安全

禁止模式至少包括：

- `eval`、`exec`、动态 `compile`；
- `os.system`、任意 `subprocess` 和 Shell；
- 网络客户端和动态包下载；
- 读取用户主目录、系统目录或其他项目；
- 读取环境变量中的凭据；
- 改变数据、样本、指标或报告口径但不更新方案；
- 隐藏异常、伪造指标或复用旧缓存。

V1 不执行生成代码；如果未来开放执行，必须通过 AST、依赖白名单、Reviewer、测试和受限进程门禁。V1 正式训练只由受控 Worker 执行。

## 9. 项目存储结构

建议的逻辑结构：

```text
local-data-root/
└── projects/<project_id>/
    ├── datasets/        原始与清洗版本，本地受控
    ├── artifacts/       画像、表格、代码、模型、报告
    ├── runs/            运行清单与 checkpoint
    ├── temp/            可清理临时文件
    └── audit/           脱敏审计事件
```

- 项目 ID 由系统生成，不直接使用用户文件名作为路径；
- 所有路径在解析后校验仍位于项目根目录；
- 产物写入先临时后原子替换；
- 删除项目需要明确列出影响范围和确认；
- 运行缓存与正式产物分开。

## 10. 日志与 Trace

允许记录：

- ID、时间、状态、工具、版本、哈希、耗时、资源、错误码；
- 已脱敏的参数摘要；
- SafeEvidence Bundle 的引用和哈希。

禁止记录：

- 原始行、完整唯一值列表；
- 凭据和 Authorization Header；
- 未脱敏 LLM 请求；
- 客户级预测和解释；
- 生成代码意外打印的数据样本。

Trace 导出前再次执行脱敏检查。

## 11. Web 与本地服务

- 本地服务默认只监听回环地址；
- 使用随机端口或受控端口，并阻止非本机访问；
- 前端通过同源接口访问，不直接调用外部 LLM；
- 对修改、确认、执行和导出请求使用 CSRF/会话保护；
- 本地 API 仍需鉴权或不可预测会话令牌，不能因“在本机”而完全裸露；
- 上传文件名按显示值处理，存储路径由系统生成。

## 12. 跨平台打包边界

- 安装包包含受支持的 Python 运行时和依赖；
- macOS 与 Windows 维护各自签名、升级和凭据适配；
- 用户数据目录与程序目录分离；
- 升级不能删除项目数据；
- 卸载时明确是否保留本地项目；
- 只有在真实目标系统验收后才宣布该平台支持。

## 13. 安全阻断与告警

| 情况 | 级别 | 行为 |
|---|---|---|
| 检测到原始行进入 LLM Payload | Block | 取消请求并记录 |
| 发现直接标识符 | Block | 脱敏或拒绝 |
| 聚合组小于阈值 | Block/抑制 | 隐藏该组 |
| 生成代码请求网络/Shell | Block | 拒绝执行并要求修复 |
| 数据哈希与批准方案不符 | Block | 重新确认或重跑 |
| 外部 API 超时 | Error | 有限重试，不回退到泄漏路径 |
| 日志脱敏失败 | Block | 不写入、不导出 |

## 14. 安全验收

V1 至少需要：

- 原始数据外发负向测试；
- 敏感字段名和值的 DLP 测试；
- 路径穿越测试；
- API Key 泄漏扫描；
- 生成代码危险调用测试；
- Worker 网络和目录权限测试；
- 小样本聚合抑制测试；
- Trace 导出脱敏测试；
- 安装升级不丢数据测试。

通过这些测试只证明已实现相应机制，不等于监管合规认证或生产安全保证。
