## 1. 结论

当前分支新增了本地 Evaluation Harness、受控超参数搜索、模型包兼容性报告、离线依赖包脚本及报告可访问性元数据。实现边界总体清楚，也明确没有把合成 Smoke 结果宣传为真实业务效果。

但在把 Harness 用作 Baseline/Candidate 发布门禁之前，仍有 5 项高优先级问题需要解决：

1. Suite 可以原地覆盖，而 Run 没有保存不可变 Suite/Gate 快照；
2. Baseline 比较按列表位置配对并忽略数量差异，同时不允许声明“受控变更维度”；
3. 安全门禁没有检查 raw record、隐藏思维链、严重度和关键用例逐项通过；
4. Case timeout 只停止轮询，不能停止实际执行；
5. 离线依赖包缺少仓库锁文件，且只按包名检查 wheel，无法证明可离线安装。

因此当前成熟度应表述为：**可运行的本地评测基础和合成验证框架，尚不是可信的发布门禁或可复现离线发行链路。**

| 等级 | 数量 | 含义 |
| --- | ---: | --- |
| P0 | 0 | 未发现需要立即停止开发的数据破坏或远程利用问题 |
| P1 | 5 | 会让评测门禁、超时隔离或离线交付给出错误结论 |
| P2 | 9 | 影响可恢复性、统计严谨性、可移植性、测试充分性或供应链治理 |

## 3. P1 高优先级发现

### AUD-V11-001：Suite 可覆盖，Run 没有不可变评测快照

**证据**

- `app/evaluation/harness.py:52-56`：`save_suite()` 直接覆盖 `<suite_id>.json`；
- `app/evaluation/harness.py:96-115`：启动 Run 时只写入 `suite_id` 和 `suite_version`；
- `app/evaluation/contracts.py:119-132`：`EvalRun` 不包含 Suite 内容哈希、Case 清单、Gate 配置或 Evaluator 快照；
- `tests/test_evaluation_harness.py` 没有覆盖同 ID Suite 被修改或覆盖的情况。

**影响**

同一个 `suite_id/version` 可以先后代表不同 Case、不同阈值或不同 Trial 数。历史 Run 无法从自身记录还原当时实际执行的评测合同，审计人员也无法证明 Baseline 和 Candidate 使用了同一 Suite。

**建议**

- 保存 Suite 时生成 canonical hash；相同 `suite_id + version` 内容不同则拒绝覆盖；
- 每个 Run 写入不可变 `suite_snapshot.json`，至少包含 Suite、Gate、Case 顺序、Evaluator 版本和哈希；
- Run 结果引用 snapshot hash，而不是只引用可变 Suite 文件；
- Suite 修改必须提升版本或创建新 ID。

**验收标准**

- 原地覆盖同版本 Suite 返回冲突；
- 删除全局 Suite 文件后，历史 Run 仍能独立还原完整合同；
- Run 的 snapshot hash 与实际 Case/Trial 结果逐项一致。

### AUD-V11-002：Baseline 配对和“可比性”语义会产生错误结论

**证据**

- `app/evaluation/harness.py:97-100`：Baseline 只检查 `suite_id`，不检查完成状态、Suite snapshot、Case/Trial 集合和 Gate；
- `app/evaluation/harness.py:216-223`：使用 `zip(..., strict=False)` 按位置配对，额外或缺失结果被静默忽略；
- `app/evaluation/harness.py:228-229`：只要存在一项 Manifest 比较且已有项都可比，整体即可标记 `comparable=true`；
- `app/evaluation/manifest.py:224-245`：Provider model、Prompt manifest、源码哈希等全部要求相等。

**影响**

存在两类相反错误：

1. Suite 被扩展后，只要前几个结果相同，新增或缺失 Case 可能不参与比较，形成假阳性；
2. 真正需要比较的 Prompt、模型或候选版本发生预期变化时，又会因所有字段必须相等而直接判定不可比，无法完成受控实验。

**建议**

- 用 `(case_id, trial_id)` 建立映射，要求键集合、数量和 Suite snapshot hash 完全一致；
- Baseline 必须是 `completed`，且其自身 Gate 状态可验证；
- 引入 comparison policy：明确 `allowed_differences`，例如只允许 Prompt 版本或 Provider model 变化，其余数据、策略、工具、环境必须一致；
- 对缺失、重复、额外 Case 一律 fail closed；
- 将可比性、效果回归和发布 Gate 分成三个独立结论。

**验收标准**

- 增删、重排或重复任一 Case/Trial 都会阻断比较；
- 只改变声明过的候选维度时仍可比较；
- 出现未声明变化时输出具体字段并阻断归因。

### AUD-V11-003：安全门禁未使用已经计算出的关键风险信号

**证据**

- `app/evaluation/harness.py:322-330`：摘要计算了 `raw_records_included` 和 `hidden_chain_of_thought_included`；
- `app/evaluation/harness.py:335-383`：Gate 只检查 expectation/error/security event/trace rate，没有检查上述两个布尔值；
- `app/evaluation/harness.py:171`：Case `severity` 被加入内存结果，但后续门禁完全不使用；
- `app/evaluation/harness.py:404-411`：Trace 完整性只要求 root ID、至少一个 Span 和 `events` 字段存在；
- `app/evaluation/tracing.py:317-324`：Trace Bundle 的 raw record 和隐藏思维链标记被固定写为 `False`，不是对最终导出内容的独立检测结果。

**影响**

如果脱敏逻辑未来回归、Trace 出现孤儿 Span/未终止 Span、关键 Safety Case 失败，整体 Gate 仍可能通过。可配置的平均通过率还可能掩盖单个 `critical` Case 失败。

**建议**

- 对最终序列化后的 Bundle 再执行一次 schema、父子关系、终态、Manifest hash 和递归 DLP 校验；
- Gate 强制要求 `raw_records_included=false`、`hidden_chain_of_thought_included=false`；
- `critical/high` Safety Case 必须逐项通过，不能被平均值抵消；
- 将“预期的安全阻断事件”和“非预期泄露/越权事件”分开计量；
- 保存每条 Gate check 的规则版本、输入哈希和证据路径。

**验收标准**

- 人工注入客户级记录、孤儿 Span、缺失终态、Manifest 篡改或 critical Case 失败时，Gate 必须失败；
- 风险标记来自对最终 Bundle 的验证，而非固定常量。

### AUD-V11-004：Case timeout 不能终止真实任务

**证据**

- `app/evaluation/adapter.py:130-157`：超时后只把局部变量设为 `cancelled/EVAL_TIMEOUT`；
- 代码没有取消 Run、Future 或正在执行的 Tool；
- `app/evaluation/adapter.py:24-37`：评测使用的 `EvaluationToolRunner` 直接调用 Pipeline，没有生产 Worker 的子进程终止边界；
- `app/evaluation/adapter.py:180-182` 与 `app/agents/graph.py:856-861`：随后 `engine.shutdown()` 会无限等待执行线程返回；
- `app/evaluation/harness.py:42-43`：Harness shutdown 同样使用 `wait=True`。

**影响**

配置的 `timeout_seconds` 不是 wall-clock 上限。真实 Provider、模型训练或本地库调用卡死时，评测命令/API Worker 仍可能永久占用；超时后的 Trace 导出还可能与继续运行的任务发生竞态。

**建议**

- Harness 复用生产 `WorkerProcessRunner`，或为每个 Case 建立独立可终止进程；
- timeout 时先原子标记取消，再终止进程树，并等待有限 grace period；
- 阻止终态后继续写数据库或 Trace；
- 区分 `timed_out`、`cancelled` 和 `failed`，保留明确终态证据；
- 应用关闭时不要无限等待评测线程。

**验收标准**

- 注入真实阻塞 Tool 后，进程在 `timeout + grace` 内退出；
- 超时后资源已释放，Run/Trace 不再发生写入；
- 第二个 Case 不会被第一个卡死任务永久阻塞。

### AUD-V11-005：离线依赖包不能证明完整、锁定或可安装

**证据**

- 仓库中不存在 README 示例使用的 `requirements.lock`；
- `scripts/build_offline_bundle.py:37-47` 只检查发行包名是否出现，不核对锁定版本、wheel tag、Python ABI、操作系统和架构；
- `scripts/build_offline_bundle.py:53-65` 会复制缓存中的全部 wheel，并建议执行 `pip install ... *.whl`；
- 没有检查 scikit-learn 等依赖的完整传递闭包；
- `scripts/verify_packaging.py:71` 只检查构建脚本文件存在，即可把 `has_offline_bundle_builder` 标成通过。

**影响**

名称正确但版本错误、仅有其他平台 wheel、缺少传递依赖或缓存中同时存在多个版本时，构建脚本仍可能生成看似完整的 manifest。README 中的默认命令当前也无法直接执行。

**建议**

- 提交按目标 OS/Python/架构生成的哈希锁文件，或提供可重复生成流程；
- 使用标准 requirement parser 和 wheel tag 校验，验证精确版本及传递依赖闭包；
- manifest 只列入选中的 wheel，不复制无关/冲突版本；
- 安装命令使用 `--require-hashes -r requirements.lock`，不要安装 `*.whl`；
- 在 macOS/Windows CI 的断网或 `--no-index` 干净环境真实安装并运行 smoke；
- `verify_packaging.py` 应验证锁文件、manifest 和一次实际离线解析，而非只验证脚本存在。

**验收标准**

- 错版本、错平台、错 ABI、缺少传递依赖、重复版本都在构建阶段失败；
- 目标系统干净环境可以完全断网安装、启动并执行模型包评分。

## 4. P2 中优先级发现

### AUD-V11-006：CLI `--async` 实际仍会等待，并稳定返回失败码

- `scripts/run_harness.py:35-46` 提交异步 Run 后立即进入 `finally`；
- `EvaluationHarness.shutdown()` 使用 `wait=True`；
- 打印的是提交时的 `queued` 快照，退出码判断却要求该快照为 `completed`，因此 `--async` 会等待任务结束但仍返回 1。

建议删除该参数，或让异步任务由常驻服务持有；CLI 提交成功应返回 0、Run ID 和查询方式，且不销毁执行器。

### AUD-V11-007：Harness 缺少崩溃恢复、取消和保留策略

`EvaluationHarness.__init__()` 不处理历史 `queued/running` Run；进程崩溃后状态会永久悬挂。当前也没有取消 API、重试策略、磁盘配额、保留天数或归档清理。

建议启动时将无活动租约的 Run 标为 `interrupted`，为 Run 增加 heartbeat/owner PID，并实现显式取消、重跑和配额告警。

### AUD-V11-008：评测记录保存绝对路径，工作区移动后不可复现

- `app/evaluation/harness.py:168-170` 保存绝对 result path；
- `app/evaluation/adapter.py:192-193` 保存绝对 Trace/Artifact path；
- Baseline 比较直接读取这些路径。

建议只保存相对 Evaluation Root 的受验证路径，读取时重新解析并校验目录边界；移动工作区后应继续可读。

### AUD-V11-009：调参后的 OOF 指标存在选择偏差

`app/workers/modeling.py:357-399` 先使用整份 Train 的 CV 结果选择超参数，随后 `app/workers/modeling.py:428-443` 又用同一份 Train/同一 CV 计算并展示 OOF 指标。这不是严格的 nested CV，OOF 结果会受到超参数选择信息影响。

建议使用 nested CV，或把该指标明确命名为“调参后 CV 估计”，不作为无偏 OOF 证据；最终模型比较继续以独立 Test 为准，OOT 只做最终报告。

### AUD-V11-010：搜索预算语义是“每模型”，界面容易被理解成总预算

`search_budget` 会传给每一个候选模型，最多 12 次；如果选择多个模型，真实试验数是 `模型数 × budget`，而 UI 只显示“调参试验数”。

建议改名为“每个候选模型试验上限”，同时显示预计总 Fit 数和 CV folds；或者实现全局预算调度。

### AUD-V11-011：模型包兼容性是提示，不是加载前门禁

- `app/workers/package_runtime.py:175-205` 遇到版本不一致只返回 `warning`；
- `score_package_directory()` 在加载前不调用 compatibility gate；
- `app/services/artifacts.py:269-287` 只记录部分直接依赖，并静默跳过不存在的包。

这不一定要求所有补丁版本完全相等，但当前缺少“允许的兼容范围”和实测矩阵。建议为不同算法定义最小运行依赖及受支持版本区间，对不支持的主版本阻断，对已验证兼容的小版本给出证据化放行。

### AUD-V11-012：模块导入仍会创建真实 AppContext 和线程

`app/main.py:289` 在 import 时执行 `create_app()`，会解析默认用户数据目录、创建数据库相关服务和 EvaluationHarness 线程。静态工具、测试收集或其他 Python 代码只要导入模块，就可能触碰真实应用目录。

建议使用 ASGI factory/lazy app，测试和 CLI 显式传入 `AppPaths`；模块导入本身应无文件写入、无线程、无迁移。

### AUD-V11-013：报告可访问性状态是自我声明，缺少结构验证

`app/workers/reporting.py:134-141` 固定声明表格有 caption、图表有文本替代、打印单列安全；但当前没有 HTML 可访问性测试或打印渲染测试，打印 CSS 也没有处理宽表的 `white-space: nowrap`。

建议从实际 DOM/渲染检查生成状态；增加 axe/HTML 结构检查、键盘/屏幕阅读器抽样和 PDF 打印截图回归。验证前不要把固定布尔值当成验收证据。

### AUD-V11-014：新增交付能力缺少对应自动化负例和供应链加固

- Harness 测试只有两个主路径，没有 Suite 覆盖、结果数量不一致、关键 Safety 失败、超时终止、进程重启和异步 CLI 测试；
- 离线 bundle 没有任何自动化测试；
- Python 全量依赖仍由宽范围 `pyproject.toml` 现场解析；
- GitHub Actions 使用 `actions/*@v4/v5` 标签而非 commit SHA。

建议先补本报告 P1 的负例测试，再为 release 生成约束/哈希锁和 SBOM，并把第三方 Actions 固定到审核过的 commit SHA。

## 7. 建议修复顺序

### 第一批：让评测结果可审计

1. 不可变 Suite/Gate snapshot；
2. 按 Case/Trial 键集合进行严格 Baseline 配对；
3. 引入声明式 allowed differences；
4. 最终 Trace Bundle schema、DLP、父子关系和终态校验；
5. critical/high Safety Case 逐项 fail closed。

### 第二批：让 Harness 可运营

1. Case 独立进程和真实超时终止；
2. 崩溃恢复、取消、heartbeat、磁盘配额；
3. 相对路径与工作区移动测试；
4. 修复或移除 CLI `--async`。

### 第三批：让模型与离线发行证据可信

1. nested CV 或重命名调参后 CV 指标；
2. 明确每模型/全局搜索预算；
3. 生成哈希依赖锁和完整 wheel 闭包；
4. 目标 OS 断网安装 smoke、模型包 clean-env 评分；
5. 固定 Actions SHA、生成 SBOM，并保留 CI 产物哈希。

## 8. 推荐新增测试清单

- [ ] 同 ID/同版本 Suite 内容变化必须失败；
- [ ] Run 保存不可变 Suite/Gate snapshot 和 hash；
- [ ] Baseline 多/少/重排/重复 Case 均失败；
- [ ] 只允许声明的 Prompt/模型候选差异；
- [ ] raw record、PII、隐藏思维链、孤儿 Span、未终止 Span 均阻断 Gate；
- [ ] critical Safety Case 失败不能被平均通过率掩盖；
- [ ] 真实阻塞 Tool 在 timeout 后被杀死且不再写入；
- [ ] Harness 进程重启后 queued/running Run 转为可解释终态；
- [ ] `--async` 提交后立即返回 0，或删除该参数；
- [ ] 工作区移动后历史评测仍可读取和比较；
- [ ] nested CV/独立 Test 指标来源在报告中可区分；
- [ ] 错版本、错平台、错 ABI、缺传递依赖的 wheel cache 构建失败；
- [ ] macOS/Windows 完全 `--no-index` 安装、启动、模型评分和卸载通过；
- [ ] 报告 HTML 通过结构化可访问性检查和打印渲染回归。

## 9. 最终判断

当前分支适合继续作为**本地评测研发基础**，但在 AUD-V11-001 至 005 关闭前，不建议把 Harness Gate 直接接入正式发布阻断，也不建议把离线 bundle 脚本作为“已经可交付的离线安装包”对外说明。

最关键的改造不是继续增加更多 Evaluator，而是先保证：**同一合同可复现、比较对象严格对齐、关键安全项不可被平均值掩盖、超时真的能停、离线包真的能在目标机断网安装。**
