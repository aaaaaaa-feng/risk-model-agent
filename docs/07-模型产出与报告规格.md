# 07｜模型产出与报告规格

- 文档版本：v1.0
- 日期：2026-08-20
- 目标：定义专业、可复现、无口径矛盾的模型产物与报告

## 1. 产出原则

1. 所有数字来自不可变本地运行产物，不由 LLM 计算或改写。
2. 页面、JSON、Excel/HTML 报告使用同一指标源。
3. 每份报告绑定数据、方案、代码、模型和工具版本。
4. 报告区分事实、风险、建议和未验证事项。
5. 离线指标不描述为生产效果、业务收益或合规结论。
6. 失败、不可计算和缺失指标必须明确显示，不能用 `0` 或旧缓存替代。

## 2. 运行产物目录

一次成功 Run 至少包含：

```text
run-manifest.json
data-profile.json
eda-summary.json
cleaning-plan.json
cleaning-result.json
feature-selection.json
model-plan.json
generated-code/
code-review.json
tests-summary.json
models/
metrics.json
scorecard/              仅适用时
explanations/           树模型等
report.html
report.xlsx
audit-summary.json
checksums.json
```

文件名可以内部调整，但语义和版本必须稳定。

## 3. Run Manifest

`run-manifest.json` 至少记录：

- `project_id`、`run_id`；
- 创建和完成时间；
- 数据版本、哈希、行列数；
- Y 字段别名、0/1 含义；
- 样本范围与切分；
- 清洗、筛选、模型计划版本；
- Agent、Prompt、模型、工具版本；
- Python 与依赖版本；
- 随机种子、线程和资源配置；
- 所有产物引用与哈希；
- 运行状态与已知限制。

Manifest 不包含原始客户数据。

## 4. 数据质量与探索报告

### 必须包含

- 文件与数据版本；
- 行数、列数、内存估计；
- 字段角色和类型；
- 缺失、唯一值、常量、高基数；
- 重复行/实体检查结果；
- Y 的 0/1 分布与异常值；
- 时间覆盖和按时间的样本/Y 分布；
- 重点单维和多维画像；
- 疑似标识符、贷后字段和泄漏风险；
- 清洗前后差异。

### 多维分析说明

报告标注维度、指标、过滤、分箱、Top-K、小样本阈值、隐藏/合并组数。不得只展示图而不提供统计口径。

## 5. 变量筛选报告

### 汇总漏斗

- 原始字段数；
- 基础质量排除；
- 泄漏/时间不可用排除；
- IV/单变量筛选；
- 稳定性筛选；
- 相关性/共线性处理；
- 最终变量数。

### 字段明细

每个字段至少记录：

- 字段名或别名；
- 角色与类型；
- 缺失、唯一值；
- IV/WOE、单变量 AUC/KS（适用时）；
- PSI/时间稳定性；
- 相关簇或 VIF（适用时）；
- 入选/排除；
- 主原因和次要提示；
- 人工/策略覆盖记录；
- 指标计算使用的样本范围。

高 IV 也可能是泄漏信号。报告不能把 IV 越高描述为无条件越好。

## 6. 模型候选报告

### 模型集合

- WOE + Logistic Scorecard；
- Logistic Regression；
- Random Forest；
- XGBoost；
- HistGradientBoosting。

### 公平比较要求

- 相同数据版本；
- 相同训练/验证/OOT 定义；
- 相同候选变量基线，允许记录明确的模型专属预处理；
- 相同主评估指标与模型选择规则；
- 调参不使用最终留出/OOT；
- 失败候选保留错误与尝试信息。

### 验证协议（当前 V0.1 冻结）

- 当前版本不做超参数调优；填补、编码、标准化和 IV/WOE 等参数只在训练分区拟合；
- 验证集用于候选比较和阈值选择；
- 模型选择规则和阈值锁定后，OOT/最终留出集只评估一次；
- OOT 不得参与 IV、WOE、分箱、填补、相关性、调参或阈值选择；
- 每个指标必须记录 `fit_scope`、`eval_scope` 和验证协议版本（当前为 `risk-validation/holdout-v1`）；
- 后续若引入训练集内交叉验证，必须升级协议版本并重新跑回归测试；所有候选、既有基线模型和 what-if 实验必须声明是否遵守同一协议。

## 7. 指标规格

| 指标 | 用途 | 说明 |
|---|---|---|
| ROC-AUC | 排序能力 | 类别极不平衡时不能单独使用 |
| Gini | 排序能力 | 通常由 `2*AUC-1` 推导，需标注 |
| KS | 好坏样本分离 | 报告阈值与计算样本 |
| PR-AUC | 不平衡样本 | 同时报告正类比例基线 |
| Lift | 分层捕获 | 明确分组与累计/非累计口径 |
| Brier | 概率误差 | 与校准共同解释 |
| Calibration | 概率可靠性 | 展示分箱与样本量 |
| Confusion Matrix | 阈值表现 | 阈值来源必须明确 |
| Recall/Precision | 业务阈值 | 不将默认 0.5 当作唯一阈值 |
| PSI | 稳定性 | 阈值仅为策略参数，不是普遍定律 |

所有指标必须包含：值、数据分区、置信/波动信息（可用时）、不可计算原因和实现版本。

## 8. 模型选择

冠军建议不只按单一最高 AUC 排序。模型选择规则可综合：

- 验证/OOT 排序能力；
- 校准；
- 稳定性；
- 解释性；
- 变量数量；
- 运行资源；
- 评分卡需求；
- 失败和风险提示。

规则在查看最终留出/OOT 前冻结。报告展示规则和每个模型的得分依据。

## 9. 评分卡规格

评分卡只适用于经验证的 WOE + Logistic 路线。必须包含：

- 分箱方法与版本；
- 缺失、特殊值和未知类别处理；
- WOE、IV、样本量与坏样本率；
- 单调性和业务合理性；
- 逻辑回归系数、方向和显著性/稳定性信息；
- Base Score、PDO、Odds 和公式；
- 每个变量分箱的分值；
- 总分范围与校验；
- 评分到概率的映射；
- 训练/验证/OOT 表现；
- 边界和未知输入测试。

树模型不生成传统评分卡。它们输出变量重要性、局部/全局解释和相应风险说明。

## 10. 基线、what-if 与报告叙事

- `BaselineModel` 可以是既有模型分数列或经明确格式校验的模型包；比较必须使用同一冻结样本、同一指标协议和固定通过率下的捕获率/swap set；
- what-if 实验从当前方案 fork，只重算受影响依赖闭包，默认标记为“实验结果，未审核”，不能污染正式报告；
- 报告文字由 Agent 基于已验证产物起草，表格、指标和图只能来自确定性 Worker；专家可逐段修改、锁定，锁定文本和证据引用参与报告哈希；
- 正式报告应单独展示“候选 vs 既有基线”和“实验 vs 正式 Run”，避免把实验探索当成已批准结论。

## 11. 代码审核报告

`code-review.json` 和页面摘要包含：

- 主代码版本和哈希；
- Reviewer 模型与 Prompt 版本；
- `pass/warn/block`；
- 每个问题的代码、级别、位置、证据和修复要求；
- 修复轮次与版本链；
- AST/依赖/危险调用检查；
- 单元、合成和一致性测试；
- 未解决警告；
- “未发现阻断问题”的结论，不作绝对保证。

## 12. 专业模型报告结构

1. 封面与版本；
2. 执行摘要；
3. 目标、范围和业务假设；
4. 数据来源与安全边界；
5. Y、观察窗口、表现窗口与样本切分；
6. 数据质量与探索性分析；
7. 清洗与预处理；
8. 变量筛选；
9. 候选模型和参数策略；
10. 验证方法与指标比较；
11. 冠军建议与替代模型；
12. 评分卡或模型解释；
13. 稳定性、校准和敏感性；
14. 代码审核与测试；
15. 限制、风险和下一步；
16. 版本、审计和产物清单。

## 13. 导出格式

### V1 必须

- HTML：完整可阅读报告；
- XLSX：字段、分箱、变量筛选、指标和评分卡明细；
- JSON：机器可读结果与 Manifest；
- Python：可复现代码；
- 模型包：本地使用的模型和预处理产物；
- Checksums：所有正式产物哈希。

模型包必须记录序列化格式和加载策略：XGBoost 使用原生 `save_model`；scikit-learn 记录 Python/依赖版本、参数和安全加载限制。不得把不受信任的 pickle 当作通用交换格式。

### P1 可选

- PDF 固化版；
- 独立图表图片；
- 面向模型管理平台的导出适配。

## 14. 报告状态

| 状态 | 含义 |
|---|---|
| Draft | 运行完成但仍有待确认警告或未完成复核 |
| Validated | 确定性校验、Reviewer 和报告一致性通过 |
| Superseded | 上游数据或方案变化，被新版本取代 |
| Invalid | 发现数据、代码或指标一致性问题 |

V1 不使用“正式生产模型”“监管通过”等状态。

## 15. 结果一致性检查

- 页面指标与 `metrics.json` 一致；
- HTML/XLSX/JSON 的模型名、样本量和指标一致；
- 评分卡分值与模型概率映射通过固定样例校验；
- 报告引用的字段数与筛选产物一致；
- 报告版本与 Run Manifest 一致；
- 失败候选不会显示成功指标；
- 新 Run 失败不会复用旧 Run 的冠军或图表。

## 16. 免责声明与事实边界

报告必须说明：

- 结果属于指定数据、样本和切分下的离线实验；
- 泄漏检测是规则和证据筛查，不能替代字段血缘核验；
- 模型表现不等于未来生产表现或业务收益；
- 公平性、合规性、拒绝原因和上线审批需要独立流程；
- 合成演示数据只证明流程可运行。
