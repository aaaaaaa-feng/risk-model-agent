# 01｜产品需求文档 PRD

- 产品暂定名：风控建模 Agent
- 文档版本：v1.0
- 日期：2026-08-20
- 状态：需求基线，研发实现前确认

## 1. 产品定义

风控建模 Agent 是一个本地优先、外部 LLM 辅助的二分类风控建模工作台。它帮助风控建模人员完成数据导入、探索性分析、数据清洗、变量筛选、建模方案设计、代码生成与审核、本地训练、模型比较、评分卡和专业报告输出。

产品不是普通聊天机器人。用户在一个有状态的项目中与主 Agent 多轮协作，系统持续展示当前节点、调用工具、分析证据、Reviewer 反馈、进度、风险和产物。

产品不是自动授信系统，不直接作出通过、拒绝、调额或定价决定。

## 2. 背景与问题

传统风控建模通常需要在多个脚本、表格、Notebook 和报告模板之间切换。流程中常见的问题包括：

- 数据集质量与 Y 定义未确认就开始训练；
- 清洗和变量筛选规则散落在代码中，难以复现；
- 高维变量直接入模，缺少 IV、缺失、稳定性和泄漏筛查；
- 不同模型使用不同样本或切分，指标无法公平比较；
- AI 生成长代码后缺少独立审核与执行验证；
- 过程状态、工具调用、人工确认和报告口径没有统一记录；
- 原始数据上传云端会带来不可接受的数据安全风险。

本产品要解决的是“让建模过程更自动、更透明、更可恢复”，而不是用 LLM 替代确定性统计和模型计算。

## 3. 目标用户

### 3.1 核心用户

- 消费金融、银行、小贷、互联网金融等场景中的风控建模人员；
- 熟悉业务口径和基本模型指标，但不希望人工审查大段生成代码；
- 需要在普通办公电脑上完成离线建模实验的人。

### 3.2 次要用户

- 风控策略人员：关注样本定义、变量解释和报告；
- 模型负责人：关注可复现性、审核记录和模型比较；
- 内部技术人员：关注本地部署、权限、日志和故障恢复。

### 3.3 不面向的用户

- 希望系统直接替其作出授信决策的业务人员；
- 希望上传任意数据后无需定义 Y 和样本口径即可得到“最佳模型”的用户；
- 需要实时线上推理、生产流量灰度或模型监控的平台团队。

## 4. V1 目标

1. 在普通 8GB 内存电脑上，完成受限规模数据的本地分析与二分类建模。
2. 支持 CSV、XLSX 导入，保存数据版本和哈希。
3. 让 Agent 先分析数据，再请求必要的业务确认，而不是直接训练。
4. 支持探索性分析、清洗、变量筛选、模型比较和报告闭环。
5. 支持主 Agent 与 Reviewer Agent 的生成、审核、修复、重审循环。
6. 支持自动运行模式和半信任模式。
7. 通过 Web 工作台流式展示节点、进度、工具、风险和产物。
8. 保证原始数据留在本地，只向外部 LLM 提供安全聚合证据。
9. 为后续独立评测 Harness 预留版本化 Trace 接口，但不在 V1 内建设评测平台。
10. 为 macOS 与 Windows 安装包设计稳定的本地服务边界。
11. 支持专家高频的报告叙事、既有模型基线比较、what-if 实验和数据字典辅助，而不牺牲正式 Run 的可复现性。

## 5. 成功标准

产品成功不以某一份数据上的 AUC 高低作为唯一标准。V1 的成功标准是：

- 核心流程完成率：符合数据契约的演示任务可从导入走到报告；
- 过程正确性：状态、样本、变量、代码和模型版本可追溯；
- 数据安全：自动测试和审计中不存在原始记录外发；
- 结果一致性：页面、JSON、Excel/HTML 报告中的指标来自同一运行产物；
- 可恢复性：刷新页面或应用重启后可恢复到最近安全节点；
- 可理解性：用户无需阅读代码即可确认 Y、样本、排除字段、清洗、筛选和模型；
- 跨平台真实性：仅在对应系统完成安装和验收后标记该平台可用。

## 6. V1 核心流程

1. 创建本地项目。
2. 导入 CSV 或 XLSX，完成文件校验和数据版本绑定。
3. 本地完成字段、缺失、唯一值、类型、时间和 Y 候选分析。
4. 主 Agent 基于安全证据提出 Y、样本和分析计划。
5. Reviewer Agent 审核计划；半信任模式下展示给用户确认。
6. 本地执行探索性分析与数据质量检查。
7. 如数据不标准，生成清洗方案，审核后本地执行并重新画像。
8. 使用缺失率、唯一性、泄漏、IV/WOE、稳定性、相关性等分层筛选变量。
9. 确认最终变量集、样本切分和候选模型。
10. Code Agent 从冻结方案生成可导出的代码。
11. Reviewer Agent 审核代码；静态检查和本地测试共同决定是否可执行。
12. 本地训练多个候选模型，锁定规则后在留出/OOT 样本上评估。
13. 输出模型比较、评分卡或树模型解释、专业报告和审计清单。

## 7. 功能需求

### FR-001 项目与会话

- 每个项目有独立 `project_id`、数据版本、会话、运行和产物。
- 支持多轮对话、关闭后继续、暂停、取消、失败重试。
- 用户修改关键决定后，系统必须使受影响的下游结果失效。

### FR-002 数据导入

- V1 必须支持 `.csv` 与 `.xlsx`。
- 支持编码、分隔符、Sheet 选择和类型预览。
- 不静默合并多个文件；多表关联后置。
- XLSX 默认使用低内存/只读解析；导入前根据文件大小、行列数估算内存，超出支持边界时先拒绝并说明原因。
- 导入后记录文件名、大小、哈希、行列数和时间。

### FR-003 Y 与样本确认

- Y 必须明确为 0/1，并确认 1 代表坏样本还是好样本。
- 检查缺失、异常标签、单一类别、极少数类别和时间窗口。
- 支持随机分层切分和时间切分；存在可靠时间字段时优先建议时间留出。
- 必须明确训练、验证、留出/OOT 的用途，避免重复使用留出集调参。

### FR-004 探索性分析

- 输出数据规模、字段角色、缺失、唯一值、分布、异常、重复和时间覆盖。
- 支持单维、双维、三维、四维分群分析。
- 支持按样本量、坏样本率、缺失率等指标钻取。
- 高维交叉必须有 Top-K、最小样本量、分箱和组合数限制。

### FR-005 数据清洗

- 区分安全自动处理、需要策略确认和禁止静默处理三类动作。
- 类型标准化、空白字符、缺失标识等可自动处理。
- 异常值截断、稀有类别合并、样本删除等必须留下前后证据。
- 修改 Y、观察窗口、实体去重口径不得由 Agent 静默决定。
- 所有预处理参数只在训练数据上拟合。

### FR-006 变量筛选

- 基础规则：常量、近零方差、高缺失、高基数、ID、重复字段。
- 风险规则：贷后字段、目标泄漏、可用时间晚于决策时间。
- 单变量指标：IV/WOE、单变量 AUC/KS、缺失与类别分布。
- 稳定性指标：时间分布、PSI、训练/验证差异。
- 多变量处理：相关性聚类、共线性与模型约束。
- 每个变量必须记录入选/排除原因和规则版本。
- 支持导入可选数据字典（字段名、中文名、口径、来源和角色）；数据字典也纳入脱敏、版本和审计边界。

### FR-007 模型候选

- WOE + Logistic Scorecard；
- Logistic Regression；
- Random Forest；
- XGBoost；
- HistGradientBoosting。
- 允许导入一个既有模型分数列作为 `BaselineModel`，与候选在同一冻结样本上比较。

所有模型使用同一冻结样本、同一数据版本和可比较的验证协议。算法可以有各自预处理，但必须记录差异。

### FR-008 代码生成与审核

- Code Agent 只能依据已冻结的结构化方案生成代码。
- Reviewer Agent 使用独立上下文审核方案和代码。
- 审核输出必须结构化为 `pass`、`warn` 或 `block`。
- `block` 触发修复，最多自动修复三轮。
- AI 审核不能替代静态检查、本地测试和执行结果校验。
- V1 生成代码是交付物，不在产品内执行；默认由受控 Worker 执行训练，任意生成代码不得直接获得 Shell、网络和全盘文件访问。

### FR-009 双运行模式

- 自动运行模式（对应用户所称“完全信任模式”）：在已配置策略内自动推进，遇到硬阻断必须停止。产品界面不使用“完全信任”作为正式名称，避免误导用户认为安全约束已关闭。
- 半信任模式：Agent 与 Reviewer 先完成分析，再让用户确认关键业务决定。
- 两种模式均不能绕过数据安全、目标合法性、泄漏、代码安全和测试门禁。

### FR-010 多轮交互与反馈

- 对话必须绑定项目和运行状态，不依赖单次问答。
- 用户可在任意可中断节点追问、修改、暂停或取消。
- Agent 回复支持点赞、点踩和原因反馈。
- 点赞/点踩只表示回复质量，不等于正式批准。
- 正式确认必须使用独立的确认动作和审计记录。

### FR-011 状态与进度

- 显示当前节点、节点状态、Agent、工具、进度、警告、阻断和下一步。
- Agent 之间的结构化消息默认折叠，可按需展开。
- 不展示隐藏思维链；展示依据、结论、工具结果和决策摘要。

### FR-012 报告与产物

- 数据质量与探索报告；
- 清洗和变量筛选报告；
- 模型比较与验证报告；
- 评分卡或树模型解释报告；
- 可复现代码、配置、环境清单和哈希；
- Reviewer、静态检查、测试和运行审计记录。

### FR-013 本地安装与 Web

- 应用以本地服务加 Web 界面运行。
- 用户不需要手工安装 Python 或在终端执行命令。
- API Key 存于操作系统安全凭据，不进入浏览器、项目文件或 Git。
- 设置页提供 Provider、代理、模型、预算和连通性自检入口；LLM 不可用时仍可运行确定性 Worker 流程。
- macOS 与 Windows 分别生成安装包并独立验收。

## 8. 非功能需求

### 8.1 安全

- 原始行、直接标识符、原文件、模型文件和逐行预测不得发送到外部 LLM。
- 所有 LLM 请求先经过本地安全证据构建与 DLP 检查。
- Worker 默认禁止网络，文件访问限制在当前项目的受控目录。

### 8.2 性能

- 目标环境约 8GB 内存，系统必须在导入时估算内存与组合规模。
- 设计目标是最多 2 万字段的受控场景；实际支持行数/字段数以实测发布说明为准。
- 大文件或 2 万字段场景使用低内存解析、分块画像、分阶段筛选和受控并行。
- 单次 Run 和单月 LLM token/费用预算可配置，触顶时停止或降级。
- 产品必须显示预计规模风险，不能承诺任意规模数据都能运行。

### 8.3 可复现性

- 数据、方案、代码、Prompt、模型、工具和报告均版本化。
- 训练随机种子、依赖和运行配置必须写入清单。
- 失败运行不得展示旧运行指标。

### 8.4 可用性

- 用户通过常见表单、表格和步骤导航完成关键决策。
- 专业细节渐进展开；默认界面避免技术框架名和内部实现术语。

## 9. V1 明确不做

- 多分类、回归、生存分析；
- 在线授信和自动业务决策；
- 在线模型服务、灰度、实时监控；
- 任意 AutoML 和无限超参数搜索；
- 任意 Shell、任意 Python、任意 MCP 工具；
- 原始数据云端训练；
- 完整独立评测 Harness 平台；
- 把 LLM Judge 结果当作安全证明或合规认证；
- 把树模型强行转换为传统评分卡。

## 10. 关键风险与产品判断

- AI 自审相关性高：Reviewer 应支持独立模型配置，并由确定性检查兜底。
- 2 万变量可能超出 8GB：必须先粗筛、分块计算和限制多维组合。
- IV 不是唯一筛选依据：需要结合泄漏、稳定性、相关性和业务可用时间。
- 随机切分可能高估效果：存在时间信息时优先设计 OOT。
- “自动清洗”可能改变业务定义：语义性操作必须留证或确认。
- 模型效果依赖数据：产品验收不能预设必然达到某个 AUC/KS。
- LLM 不可用、企业代理限制或费用触顶：确定性流程仍可使用，Agent 结论显示为不可用。
- 既有模型、what-if 实验和报告叙事：作为专家高频路径纳入 V1.x，实验结果必须与正式报告隔离。

## 11. 尚未冻结的配置项

以下内容不阻塞架构设计，但在真实 LLM 接入和打包前必须确认：

- 首个外部 LLM 供应商、模型和服务条款；
- 安全证据的最小分组样本阈值；
- 首版支持的最大文件、最大行数（字段数的设计目标已冻结为最多 2 万，实际支持值由实测确定）；
- macOS 最低版本、Windows 最低版本；
- 是否在 P1 增加旧版 `.xls`；
- 企业部署时的日志保留和数据删除策略。
