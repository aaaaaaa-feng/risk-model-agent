# 01｜风控建模 Agent V1 产品需求文档

状态：V1 正式基线
适用对象：消费信贷风控建模人员
事实边界：本文描述 V1 范围；是否可正式生产部署仍需机构级验证。

## 1. 产品定义

风控建模 Agent 是一个本地优先的二分类建模工作台。核心用户懂 AUC、KS、IV、Lift、PSI 等业务指标，但不希望手写整套工程代码，也不应被要求审核长代码。

产品不是聊天机器人，也不是让多个 Agent 自由讨论的演示。它把项目、数据版本、Y 任务、Run、确认、Reviewer、报告和评分组织成可暂停、可恢复、可审计的流程。

## 2. 核心价值

- 用户在一个 Web 工作台内完成多表导入、关联、建模、报告和批量评分。
- 原始数据与逐行结果不由产品上传到外部 LLM；外部模型只看到本地 DLP 后的聚合 SafeEvidence。
- Agent 负责分析、计划、解释和修复；确定性 Worker 负责统计、训练和产物，避免 LLM 直接计算指标。
- Reviewer 先于用户检查计划与代码，并最终审核执行证据和报告。
- 每个决策都有状态、事件和证据，页面不展示隐藏思维链。

## 3. V1 范围

### 3.1 数据与项目

- CSV、XLSX、XLSM、XLS；Excel 多 Sheet 必须明确选择。
- 基准样本表、任意数量特征表、数据字典和待评分表。
- 客户维度或订单维度；二要素/三要素及其他组合键。
- 项目归档、回收站、本地备份、加密迁移包和升级快照。
- 典型规模约 3 万行、1000 字段；不写死上限，按资源动态分批和降级。

### 3.2 多表关联

按顺序提供四级能力：Agent 推荐关联键、可视化编辑、Agent 生成 Notebook、用户手写 Notebook。任何路径的输出都必须重新检查粒度、唯一性、重复、匹配率、行数膨胀、Y 分布和血缘。

### 3.3 多 Y 任务

- Y 必须是二分类语义，合法建模样本为 0/1。
- `-1` 与空值表示当前 Y 未表现或不可用，按 Y 独立排除。
- 每个 Y 独立冻结样本、切分、IV、分箱、模型和报告。
- 多 Y 顺序排队；一个 Y 失败或被用户停止，不影响其他 Y。

### 3.4 建模流程

项目创建 → 数据导入 → 关联 → Y 确认 → 建模前诊断 → 清洗 → Train/Test/OOT → 变量筛选 → 分箱 → 模型方案 → 代码生成与审核 → 训练/调参/校准 → 报告审核 → 模型包 → 批量评分。

默认筛选参考值：IV 0.02、相关系数 0.70、缺失率 30%。这些值可调整，不是行业真理。普通变量可填写业务理由恢复；PII、泄漏、其他 Y、贷后不可用字段和主键不可恢复。

### 3.5 算法与评分

- Dummy、WOE Logistic Scorecard、正则化 Logistic。
- Random Forest、Extra Trees、XGBoost、LightGBM、CatBoost。
- 按资源推荐组合并顺序执行，不默认跑全量算法。
- 比较未校准、Platt、Isotonic；只用 Train/CV 和 Test 选择，OOT 只进入最终报告。
- 默认 300—900，高分代表低风险；600 分对应好坏比 20:1，PDO 50。
- 保留未截断原始分值，并报告封顶与封底比例。

## 4. 协作模式

- 半信任：Reviewer 预审后，在 Y、清洗、切分、筛选、分箱、模型方案等阶段等待用户确认；用户不需要阅读代码。
- 完全信任：Reviewer 通过后自动继续；安全阻断、数据合同错误和不可恢复字段规则仍不可绕过。

Reviewer 最多进行三轮“发现问题 → 反馈主 Agent → 受控修复 → 重审”，随后仅允许明确标注的安全降级。不能把降级结果冒充成 LLM 审核通过。

## 5. 报告与部署产物

- 管理摘要与专业详情。
- Train/Test/OOT 样本量、好坏样本、坏占比、AUC、KS、PR-AUC、PSI。
- 10 箱/可配置分箱的坏占比、Lift、累计捕获、概率区间和排序性。
- 候选模型对比、最终入模变量、重要性、WOE/分箱、校准和治理证据。
- Excel、单文件 HTML、JSON、可复现 Notebook、模型包和独立评分入口。
- sklearn 用 skops，XGBoost 用 JSON，LightGBM 用文本模型，CatBoost 用 CBM；评分卡用 JSON 规则。

AUC/KS 是参考，不是硬编码准入。Test 等频箱未绝对排序时可保留产物用于分析，但质检只能标记“条件通过”，不能显示为无条件通过。

## 6. Provider 与对话

首批支持 DeepSeek、Kimi 开放平台、Kimi Code、OpenAI、Anthropic 和自定义兼容端点；支持 OpenAI Chat Completions 与 Anthropic Messages 两种协议。设置中心允许使用未保存表单值测试连接。

项目对话支持多轮持久化、消息反馈和流式摘要。对话用于解释当前状态、收集业务修改和导航流程，不替代结构化确认。

## 7. V1 不做

- 多分类、回归、时序预测和无监督模型。
- 多用户登录、权限管理、内网多人协作和生产服务治理。
- 任意 MCP 工具发现或任意远程代码执行。
- 内置独立评测 Harness 平台。
- 承诺阻止用户 Notebook 代码或第三方包主动外传数据。
- 未签名安装包的正式生产发布宣称。

## 8. 完成定义

固定种子多表演示完整跑通；核心 Python、TypeScript、API、黄金数据、报告一致性、安全、迁移和打包检查通过；1440×900 与 1280×800 页面完成键盘、溢出、空/阻断/运行/完成状态检查；旧数据先备份迁移，旧实现和生成残留删除；GitHub 远端 SHA、默认分支、CI 和产物状态经实际核验。
