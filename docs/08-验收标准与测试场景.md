# 08｜验收标准与测试场景

- 文档版本：v1.0
- 日期：2026-08-20
- 目标：把产品要求变成研发、测试和用户可共同检查的结果

## 1. 边界说明

本文定义当前产品的软件验收和端到端场景，不是独立 Agent 评测 Harness 平台。

当前项目仍必须有普通单元测试、集成测试、端到端测试和安全测试。未来 Harness 会读取本产品 Trace，批量运行 Golden/Bad Case、重复试验、Judge 和回归门禁，但不属于本阶段交付。

## 2. 验收层级

| 层级 | 关注点 |
|---|---|
| L1 合约 | Schema、状态迁移、工具输入输出 |
| L2 Worker | 统计、筛选、训练、指标、报告正确性 |
| L3 Agent | 计划、审核、修复、工具选择和多轮状态 |
| L4 产品流程 | 用户从导入到报告的完整任务 |
| L5 安全 | 数据外发、权限、路径、凭据和代码执行 |
| L6 跨平台 | macOS/Windows 安装、运行、升级和卸载 |

## 3. 发布硬门禁

以下任一失败，不得标记 V1 完成：

- 原始数据可能进入外部 LLM 请求；
- Y 不满足明确 0/1 仍可训练；
- 数据/方案哈希不匹配仍可沿用批准；
- 变量筛选或预处理使用最终留出/OOT 拟合；
- Reviewer `block` 可被主 Agent 绕过；
- 危险生成代码可执行；
- 页面、报告和 JSON 指标不一致；
- 刷新/重启后把失败或运行中状态误判为成功；
- 安装包需要用户手工配置开发环境才能启动；
- 目标系统未真实验收却对外宣称支持。

## 4. 核心端到端场景

### AC-001 正常二分类闭环

给定一份包含明确 0/1 Y、时间字段、数值与类别变量的合成 CSV，当用户选择半信任模式并完成必要确认时：

- 系统完成本地画像；
- 主 Agent 生成分析与建模计划；
- Reviewer 审核；
- 完成探索、筛选、至少两类模型、比较和报告；
- 页面和导出指标一致；
- Trace 包含所有节点和工具状态；
- 外部请求不含原始行。

### AC-002 XLSX 导入

给定多 Sheet XLSX：

- 用户可选择目标 Sheet；
- Sheet、文件哈希和解析配置被记录；
- 错误 Sheet 不会静默使用第一张表；
- 后续 Run 绑定正确数据版本。

### AC-003 Y 含异常标签

给定 Y 包含 `0/1/-1/空值`：

- 系统显示各取值数量；
- 不得自动把 `-1` 和空值转成任一类别；
- 在策略未确认前阻断训练；
- 修复后产生新数据/方案版本。

### AC-004 单一类别和极少数类别

- Y 只有一种类别时必须阻断；
- 少数类过少时显示样本和统计风险；
- 不伪造 AUC、KS 或交叉验证结果。

### AC-005 时间切分

给定可靠申请时间字段：

- 系统建议时间切分；
- 展示训练、验证、OOT 的时间范围和 Y 分布；
- 最终 OOT 不参与清洗、筛选、调参或阈值选择。

### AC-006 泄漏字段

给定 `post_loan_overdue_days` 等贷后字段：

- 检测结果包含字段、规则和依据；
- 高置信泄漏进入阻断；
- 自动运行模式也不得跳过；
- 历史风险字段不会仅因含“逾期”词就一律误判，应结合前缀、角色或用户证据。

### AC-007 清洗回路

给定混乱缺失标识、日期类型和异常类别：

- 生成清洗计划和前后影响；
- Reviewer 检查计划；
- 半信任模式下用户可修改；
- 清洗后创建新数据版本并重新画像；
- 旧筛选结果标记失效。

### AC-008 高维变量筛选

给定含 2 万字段的受控测试数据：

- 系统先做元数据粗筛，再分块计算；
- 不直接把全部字段送入所有模型；
- 显示各阶段数量和进度；
- 每个排除字段有原因；
- 资源超限时降级或停止，不导致应用崩溃。

### AC-009 多维画像

用户请求“按年龄、渠道、地区、月份看样本量和坏样本率”：

- Agent 生成结构化 AnalysisSpec；
- 页面展示维度、分箱、Top-K、最小样本量和预计组合；
- Worker 本地计算；
- 小样本组合被隐藏或合并并明确提示；
- 返回可读的钻取视图，不生成无限大表。

### AC-010 变量筛选只用训练集

- IV、WOE、分箱、填补和相关性规则只在训练分区拟合；
- 测试通过构造留出集特有模式验证不存在偷看；
- Reviewer 或确定性检查发现违规时必须阻断。

### AC-011 Reviewer 修复闭环

给定含验证泄漏的种子代码：

- Reviewer 返回 `block` 与具体位置；
- 主 Agent 创建 RevisionRequest；
- Code Agent 生成新版本；
- 重跑审核和测试；
- 页面展示 v1 → v2 和修复摘要；
- v1 不被覆盖。

### AC-012 修复次数上限

当连续三轮仍未通过：

- 自动循环停止；
- 状态为阻断而非无限运行；
- 显示每轮问题和当前需要的处理；
- 不启动训练。

### AC-013 自动运行模式

- 界面显示“自动运行模式”，帮助说明其对应需求讨论中的“完全信任模式”，但不得暗示硬门禁可以关闭；
- 低风险、已配置动作自动推进；
- `warn` 按策略记录；
- Y 歧义、泄漏、安全和一致性阻断仍停止；
- 用户随时可以暂停或切换到人工处理。

### AC-014 半信任模式

- Y/样本、切分、字段、清洗/筛选、模型至少形成明确确认卡；
- Reviewer 先于用户确认；
- 用户看到的是摘要、证据和影响，不需要阅读代码；
- 确认记录绑定具体版本和哈希。

### AC-015 多轮修改与失效

完成变量筛选后，用户说“排除收入字段并改为时间切分”：

- Agent 理解为结构化修改草稿；
- 显示将失效的产物；
- 用户确认后生成新方案版本；
- 旧代码、模型和报告标记已被取代；
- 新 Run 不复用旧指标。

### AC-016 点赞与确认分离

- 点赞不推进流程；
- 点踩可以填写原因；
- 只有“确认并继续”写入 Decision 并改变状态；
- 操作记录可追溯。

### AC-017 候选模型比较

- 所有成功候选使用相同冻结验证协议；
- 报告 ROC-AUC、PR-AUC、KS、Lift 和校准等规定指标；
- 失败候选显示原因；
- 冠军规则在查看最终留出/OOT 前冻结；
- 不只按单一 AUC 自动宣称“最佳”。

### AC-018 评分卡

- 仅 WOE/LR 路线生成评分卡；
- 包含 Base Score、PDO、Odds、分箱和分值；
- 固定样例的评分与概率转换一致；
- 树模型页面不出现伪评分卡。

### AC-019 失败恢复

在训练中模拟应用退出：

- 重启后识别未完成状态；
- 不把半成品标为成功；
- 可以从允许的安全节点重试；
- 已完成的不可变上游产物不重复计算，除非版本不匹配。

### AC-020 报告一致性

- 页面、HTML、XLSX、JSON 的样本量、模型名和指标一致；
- 报告绑定正确 Run；
- 新 Run 失败不会显示旧 Run 冠军；
- 所有正式产物通过哈希清单。

## 5. 数据安全测试

### AC-S01 原始记录外发

拦截所有 Provider 请求，断言不存在原始行、标识符、完整唯一值、逐行预测和本地路径。

### AC-S02 DLP

构造手机号、身份证、卡号、地址和敏感字段名，验证阻断或别名化；同时验证正常聚合小数不会被错误识别为长号码。

### AC-S03 小样本抑制

低于策略阈值的多维组不进入 SafeEvidence；页面可在本地显示受权限控制的结果，但外部 Payload 不含该组。

### AC-S04 路径穿越

文件名和参数包含 `../`、绝对路径和符号链接时，不得读写项目根目录以外位置。

### AC-S05 代码危险调用

生成代码含网络、Shell、动态执行、环境变量和越界文件访问时，静态门禁必须阻断。

### AC-S06 凭据

仓库、日志、Trace、数据库、前端包和错误响应中不得出现真实 API Key。

## 6. 性能与资源测试

- 8GB 目标机器上测试受支持规模的导入、画像、筛选和候选训练；
- 记录峰值内存、CPU、耗时和临时磁盘；
- 验证并发上限和训练串行策略；
- 超过预算时给出可理解提示；
- 取消长任务后资源和临时文件释放；
- 支持规模在测试后写入发布说明，不能提前编造。

## 7. UI 验收

- 用户能在项目首页识别当前状态和待办；
- 每个长任务有进度、当前动作和取消；
- 阻断包含原因、依据、影响和下一步；
- 变量表支持搜索、筛选、排序、批量操作；
- Reviewer 问题和修复版本可展开；
- 键盘和屏幕阅读基础语义可用；
- 页面没有把框架名当成用户操作名；
- 合成演示数据始终有明显标识。

## 8. 跨平台验收

macOS 与 Windows 分开记录：

- 干净机器安装；
- 首次启动和本地端口；
- CSV/XLSX 导入；
- API Key 存取；
- 完整演示闭环；
- 关闭重启恢复；
- 升级保留项目数据；
- 卸载行为；
- 安装包签名/警告状态。

一个平台通过不代表另一个平台通过。

## 9. 完成定义

一个功能只有同时满足以下条件才算完成：

- 产品文档与 Schema 已更新；
- 代码已实现；
- 单元/集成/端到端测试通过；
- 安全边界已验证；
- UI 的正常、空、加载、错误和恢复状态完成；
- Trace 和审计事件完整；
- 文档不把测试结果夸大为真实业务效果；
- Git 变更范围清晰并完成审查。
