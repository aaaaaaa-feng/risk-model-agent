# 06｜UI/UX 交互规格

- 文档版本：v1.0
- 日期：2026-08-20
- 目标：让风控建模人员无需理解 Agent 框架或阅读长代码即可完成任务

## 1. 体验目标

产品应让用户始终回答三个问题：

1. 当前进行到哪一步？
2. 系统为什么这样判断，依据是什么？
3. 我现在需要做什么？

界面不是一个放大的聊天框，而是“流程工作台 + Agent 对话 + 证据与产物”。聊天用于理解、追问和修改，结构化页面用于确认、比较和操作。

## 2. 设计原则

- 任务优先：围绕建模流程组织，不按技术模块组织。
- 渐进披露：默认展示结论与风险，专业细节按需展开。
- 一处主操作：每个状态只有一个最主要的下一步按钮。
- 证据贴近结论：判断旁边可以直接查看相关数据和规则。
- 状态可恢复：刷新、退出和重启后显示真实状态。
- 术语友好：界面使用“本地计算”“代码审核”“等待确认”，不展示 Worker、Harness 等内部名词。
- 不夸大：使用“未发现阻断问题”“离线结果”，不使用“绝对正确”“生产有效”。

## 3. 信息架构

```text
项目首页
├── 新建项目
├── 最近项目
└── 本机设置

项目工作区
├── 数据准备
├── 探索与清洗
├── 变量筛选
├── 建模方案
├── 代码审核
├── 训练与验证
├── 报告与产物
└── 项目记录
```

“项目记录”展示当前产品的运行 Trace 和审计，不是独立评测 Harness。

## 4. 项目首页

### 项目卡片

每张卡片显示：

- 项目名称；
- 当前节点和状态；
- 数据版本；
- 最近操作时间；
- 待确认/阻断数量；
- 最近一次有效报告；
- “继续”主按钮。

不在首页展示大量模型指标，避免用户把某次离线结果误认为当前有效结果。

### 空状态

- “导入自己的 CSV/XLSX”；
- “使用合成演示数据体验”；
- 明确演示数据为合成数据，仅用于体验流程。

## 5. 数据导入向导

### 步骤一：选择文件

- 拖放或选择 CSV/XLSX；
- 显示文件名、大小和本地处理提示；
- XLSX 选择 Sheet；
- CSV 可自动探测编码/分隔符，失败时提供手动选项。

### 步骤二：数据预检

展示：

- 行数、列数、内存预测；
- 字段类型概览；
- 重复列名、空列、解析失败；
- 资源风险；
- “原始数据不会上传云端”状态。

### 后续确认：Y 候选

文件导入向导到数据预检结束；Y 候选、样本切分和 Agent 推荐必须在 `profile_ready` 后以确认卡出现，避免在画像证据尚未完成时提前绑定业务含义。

每个候选用卡片显示：

- 字段名或本地显示别名；
- 0/1 数量和比例；
- 缺失与其他取值；
- Agent 推荐理由；
- 风险提示。

用户必须明确 1 的业务含义。不能只提供一个“下一步”而隐藏标签语义。

### 后续确认：样本切分

- 时间切分或随机分层切分；
- 时间字段选择；
- 训练/验证/留出比例；
- 可视化每个分区的时间范围、样本量和坏样本率；
- 解释 OOT 与随机留出的差异。

## 6. 建模工作台

桌面宽屏采用三栏：

```text
┌──────────────┬──────────────────────────────┬─────────────────────┐
│ 流程与状态   │ Agent 对话 / 执行时间线      │ 当前证据与操作      │
│              │                              │                     │
│ ✓ 数据导入   │ 主 Agent：已完成数据体检     │ Y 分布              │
│ ✓ Y 确认     │ Reviewer：发现 1 个风险       │ 风险字段 3 个        │
│ ● 探索分析   │ 工具：多维画像 63%            │ [查看详情]           │
│ ○ 数据清洗   │                              │ [暂停] [修改方案]    │
│ ○ 变量筛选   │                              │                     │
└──────────────┴──────────────────────────────┴─────────────────────┘
```

窄屏可以切换三个面板，但 V1 以桌面端为主，不承诺手机端完整建模体验。

## 7. 流程导航

节点状态使用图标和文字共同表达：

- 已完成；
- 执行中；
- 等待审核；
- 等待用户；
- 有警告；
- 已阻断；
- 已失效；
- 尚未开始。

点击节点可查看历史产物，但不能越过状态机直接启动未满足条件的节点。

## 8. Agent 时间线

### 消息类型

- 事实：来自本地计算或已保存产物；
- 分析：Agent 对证据的解释；
- 风险：不确定性、泄漏或数据问题；
- 建议：下一步计划；
- 审核：Reviewer 的 pass/warn/block；
- 工具：调用名称、进度和结果摘要；
- 系统：状态、失败、恢复和失效通知。

### 消息卡片

每张 Agent 卡片可包含：

- Agent 名称和模型角色；
- 时间；
- 结论摘要；
- 证据引用；
- 展开详情；
- 追问、点赞、点踩；
- 相关结构化操作。

主 Agent 与 Reviewer 的内部通信默认折叠成“审核发现 → 修复动作 → 重审结果”，用户可展开查看问题和版本差异。

## 9. 进度反馈

长任务必须输出可理解进度，例如：

```text
正在筛选变量
阶段 2/5：计算单变量统计
已完成 1,842 / 20,000 个字段
预计剩余时间：仅在估计可靠时显示
当前警告：12 个高缺失字段
```

不展示隐藏思维链。流式区域展示节点、任务、工具、证据摘要和动作结果。

## 10. 确认卡

确认卡是正式状态操作，必须区别于聊天和点赞。

结构：

- 待确认事项；
- Agent 建议；
- Reviewer 结论；
- 依据；
- 影响范围；
- 风险与替代方案；
- 可编辑表单；
- “确认并继续”“修改”“暂不决定”。

高影响确认前显示哪些下游结果将失效。

## 11. 探索性分析页面

### 默认概览

- 数据规模；
- Y 分布；
- 缺失率分布；
- 字段类型；
- 时间覆盖；
- 高风险字段；
- 推荐继续分析的维度。

### 多维分析构建器

支持自然语言和表单两种入口：

> 按年龄、渠道和申请月份看样本量与坏样本率。

Agent 生成结构化规格后，右侧表单展示：

- 维度 1—4；
- 指标；
- 过滤条件；
- 分箱；
- 最小样本量；
- Top-K；
- 预计组合数。

用户可以修改后执行。四维分析默认使用逐层钻取，不直接渲染无法阅读的大表。

## 12. 数据清洗页面

使用“建议动作表”：

| 字段/范围 | 问题 | 建议 | 前后影响 | 风险 | 状态 |
|---|---|---|---|---|---|

支持：

- 查看清洗前后样本量和分布；
- 批量采纳低风险动作；
- 单独修改异常值、类别和缺失策略；
- 明确禁止项和阻断原因；
- 执行后自动返回重新画像。

## 13. 变量筛选页面

### 顶部摘要

```text
原始字段 20,000
基础排除 15,420
泄漏阻断 18
单变量筛选后 1,120
稳定性/相关性后 86
最终待确认 42
```

### 字段表

- 字段名/别名；
- 角色与类型；
- 缺失率、唯一值；
- IV、单变量 KS/AUC；
- PSI；
- 相关簇；
- 入选/排除；
- 原因；
- 证据详情。

支持搜索、筛选、批量排除、恢复、固定保留和导出。人工强制保留被阻断字段时仍需安全门禁，不能只靠按钮覆盖。

## 14. 代码审核页面

普通用户默认看到：

- 代码版本；
- Reviewer 结论；
- 阻断和警告数量；
- 静态检查；
- 合成测试；
- 可执行状态；
- 修复轮次和变化摘要。

高级展开才显示代码与定位，不要求用户阅读整段代码。

示例文案：

> AI 审核完成：阻断问题 0，警告 2；静态检查通过；合成数据测试通过。未发现阻止本地训练的问题。

## 15. 模型结果页面

- 候选模型比较表；
- ROC-AUC、PR-AUC、KS、Gini、Lift、Brier/校准；
- 训练/验证/OOT 区分；
- 变量重要性或评分卡；
- 失败候选及原因；
- 冠军建议与风险；
- 生成和下载报告。

默认不通过颜色暗示树模型一定优于逻辑回归。模型选择同时展示性能、稳定性、解释性和部署复杂度。

## 16. 错误与恢复

错误页面/卡片必须包含：

- 发生在哪个节点；
- 什么失败；
- 是否影响已有产物；
- 是否可重试；
- 推荐操作；
- 错误编号；
- 诊断详情入口。

如果旧 Run 已完成而新 Run 失败，界面明确保留旧 Run，但不能把旧指标显示成新 Run 的结果。

## 17. 本机设置

- LLM 供应商、Base URL、主模型、Reviewer 模型；
- API Key 状态（只显示已配置/未配置）；
- 数据目录；
- 企业代理、CA 证书和连通性自检；
- 默认运行模式；界面使用“自动运行模式”，并在帮助文案中说明其对应讨论中的“完全信任模式”，但安全硬门禁始终开启；
- CPU、内存和并行预算；
- 单次 Run / 单月 token 与费用预算，以及触顶后的停止或确定性降级策略；
- 安全证据策略摘要；
- 出站载荷日志（只读、已脱敏、可导出）；
- 日志和项目数据清理。

## 18. 可用性验收

- 新用户不阅读文档也能完成演示数据全流程；
- 用户能分辨点赞与正式确认；
- 用户能在 30 秒内找到当前节点、阻断原因和下一步；
- 变量筛选支持搜索、排序、筛选和批量操作；
- 所有长任务有可取消和真实状态；
- 键盘焦点、表单标签、颜色对比和错误提示满足基本无障碍要求；
- 专业指标提供解释，不用内部框架术语解释业务操作。
