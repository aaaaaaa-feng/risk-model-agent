## 1. 产品定位与核心用户

### 1.1 已确认的产品定位

风控建模 Agent 是一个本地优先、外部 LLM 辅助、面向二分类风控建模的项目式工作台。

核心价值不是“支持尽可能多的算法”，而是让用户在不阅读大段建模代码的情况下，安全、清楚、可追溯地完成一轮专业风控建模。

产品不直接作出授信、拒绝、调额或定价决策。

### 1.2 已确认的核心用户

核心用户是：

- 懂风控业务；
- 会看 AUC、KS、IV、PSI、Lift 等指标；
- 不会或不擅长编写完整建模代码；
- 对建模流程中的部分技术细节不熟悉；
- 其中一部分用户可以理解、修改或手写简单的数据处理 Notebook。

因此产品必须遵循：

- 业务确认优先于代码确认；
- 代码默认作为可追溯产物，不要求用户阅读；
- 技术细节由 Agent、Reviewer 和确定性工具共同处理；
- 用户主要确认 Y、样本、时间、关联、字段排除、模型候选等业务或风险决策。

## 2. 当前版本范围

### 2.1 已确认纳入

- 只支持 Y 为二分类语义的模型任务；
- 支持 CSV、XLSX；
- 支持单张建模宽表；
- 支持主样本表加一张或多张特征表的本地关联；
- 支持多个已计算好的 Y；
- 支持建模前诊断、清洗、变量筛选、分箱、候选模型、质检、报告和批量打分；
- 支持 Agent 自动执行、可视化人工操作、Agent 生成 Notebook 和用户手写 Notebook；
- 支持本地 Web 界面；
- 新项目默认半信任模式；
- 支持 macOS、Windows 的本地打包目标，但必须完成对应平台真实验收后才能宣称可用。

### 2.2 本版明确收缩

本版不建设通用数据分析或 BI 产品。原“探索分析”收缩为“建模前诊断”，只保留建模所必需的检查：

- 样本量和 Y 分布；
- 关联质量；
- 重复、缺失、异常和字段类型；
- Train、Test、OOT 差异；
- 泄漏风险；
- IV、PSI、相关性、VIF、分箱和排序性。

自由多维业务洞察、通用分析看板和洞察卡片放入后续计划。

### 2.3 后续计划，不在当前版本建设

- 内网服务器多人登录；
- 用户、角色、权限和项目隔离；
- 多任务集中调度与共享模型管理；
- 线上实时推理、发布、灰度和生产监控；
- 独立评测 Harness 平台；
- 通用多维业务分析 Agent。

当前研发应保留未来扩展边界，但不得提前实现完整多人权限体系。

## 3. 项目、Y、Run 与模型层级

已确认层级如下：

| 层级 | 定义 | 示例 |
|---|---|---|
| 项目 | 一次业务场景或一批回溯数据 | 2026 年外部数据回溯建模 |
| 数据版本 | 同一项目内的数据快照或处理结果 | 初始导入、补数版本、清洗版本 |
| Y 建模任务 | 针对一个 Y 的独立建模任务 | FPD0、FPD7、FPD30 |
| Run | 某个 Y 的一次完整或局部执行 | FPD7 首次建模、重新分箱后重跑 |
| 模型版本 | 某次 Run 产出的候选或最终模型 | FPD7_XGBoost_v1 |

一个项目可以包含多个 Y；一个 Y 可以有多次 Run；一个 Run 可以训练多个候选模型。

数据关联和公共清洗结果可以复用，但每个 Y 的有效样本、切分、IV、变量筛选、分箱和模型必须独立计算。

## 4. 项目创建与数据导入

### 4.1 项目创建

新建项目的阻塞字段只有：

- 项目名称。

以下均为可选信息，不阻碍创建：

- 项目说明；
- 产品；
- 渠道；
- 建模用途；
- 其他业务标签。

新项目默认半信任模式。

### 4.2 数据入口

项目创建后支持两个主入口：

1. 上传已经准备好的建模宽表；
2. 上传主样本表和一张或多张特征表。

必须支持：

- 多个 CSV、Excel 文件；
- Excel Sheet 选择；
- 同时上传一个或多个数据字典；
- 用户明确标记或确认主样本表；
- 文件行数、字段数、大小和读取状态可见。

### 4.3 数据快照

默认采用复制模式：

- 在项目中保存只读数据快照；
- 不修改用户原文件；
- 记录文件名、大小、哈希和导入时间；
- 原文件被移动或修改后，已创建项目仍可复现。

大文件允许使用高级“引用模式”，但必须提示源文件移动或变化会破坏复现。

### 4.4 一键演示项目

已确认保留“一键体验演示项目”：

- 使用完全合成、保存在本地的数据；
- 用户主动点击后创建，不在首次启动时自动生成；
- 可以走通数据导入、诊断、筛选、建模、质检、报告和打分流程；
- 项目页面、数据集、报告和导出产物持续标记“合成演示数据”；
- 演示指标只用于证明产品流程可运行，不得表述为真实业务模型效果；
- 演示流程在没有外部 LLM 时也应能够通过确定性降级完成。
- 演示项目使用多表合成数据，能够演示自动关联、变量筛选、建模和批量打分，并保留关联后宽表作为数据版本。
- 配置 LLM 后，用户可以主动选择“使用当前 LLM 重新分析”；演示项目不得强制先配置 API。

## 5. 多表关联与四级兜底

### 5.1 典型业务场景

主样本表通常是已经放款的客户或订单：

- 粒度可能是一人一行；
- 也可能是一笔订单一行；
- 包含一个或多个贷后 Y；
- 包含二要素、三要素或其他本地关联键。

右侧特征表可能有一至多张，通常也包含可以与主样本表匹配的二要素、三要素或唯一键。

姓名、身份证、手机号等直接标识符只能在本地参与关联，不能进入模型，也不能发送到外部 LLM。

### 5.2 四级关联链路

已确认采用四级降级策略：

1. **Agent 自动关联**：Agent 识别表角色、数据粒度、候选关联键和关联方式，Reviewer 审核后执行。
2. **可视化手动关联**：用户选择左右表、字段映射、Join 类型和重复处理方式，系统实时展示匹配率与行数变化。
3. **Agent 生成 Notebook**：Agent 生成结构化 `.ipynb`，用户逐单元格运行、修改和验证。
4. **用户手写 Notebook**：用户新建空白 Notebook 或导入已有 `.ipynb`，完全自行编写关联和处理代码。

第三级 Notebook 默认包含：

- 加载已导入表；
- 主键唯一性检查；
- 关联键规范化；
- 重复与匹配率检查；
- Merge；
- 关联前后行数变化；
- Y 分布检查；
- 输出 `modeling_dataset`；
- 注册新数据版本。

第四级是最末兜底，但不能绕过输出验收。任何 Notebook 产出的建模数据集都必须重新检查：

- 主键唯一性；
- 一对多、多对多与样本膨胀；
- 匹配率和未匹配样本；
- Y 合法性；
- 敏感字段；
- 数据血缘；
- Notebook 代码和运行结果。

Notebook 使用本地 Python Kernel，默认限制在当前项目工作区，并具有资源、网络和文件访问护栏。

Notebook 环境已确认：

- 内置 Pandas、Polars、DuckDB、Scikit-learn、XGBoost、LightGBM、CatBoost 等常用包；
- 安装其他第三方包必须由用户明确发起，记录包名、版本、来源和环境变更；
- 不允许 Agent 在后台静默安装依赖；
- 用户最终选择 Notebook 数据 Kernel 默认允许访问网络，也可以在项目设置中切换为离线模式；
- 因任意 Notebook 代码或第三方依赖都可能主动发送数据，产品不得再对启用网络的 Notebook 宣称“原始数据绝不可能离开本机”；
- 产品自身、Agent 编排和外部 LLM 调用仍严格禁止上传原始数据，只能经过 SafeEvidence 与本地 DLP；
- 页面持续显示 Notebook 网络状态，并记录系统能够观测到的依赖安装、目标地址、时间和发起任务，但不得夸大为能够审计任意代码的全部网络行为；
- 高安全项目可以切换为离线 Kernel，或只允许明确的内部地址和软件源。

## 6. 数据字典与特殊值

数据字典是正式项目资产，不是普通附件。

系统应支持映射：

- 表名与字段名；
- 中文含义；
- 数据类型与单位；
- 枚举值；
- 特殊值；
- 主键、Y、时间字段和普通变量角色；
- 来源与时间口径。

系统输出字典覆盖报告：成功匹配、无字典说明、字典中不存在于数据的字段、类型冲突等。

特殊值处理优先级已经确认：

1. 数据字典明确说明；
2. 用户手动指定；
3. Agent 根据分布提出怀疑和建议；
4. 无足够证据时保持原值，不自动修改。

缺少或不完整的数据字典不阻断普通变量分析；以下字段语义不清时可以阻断：

- Y；
- 关联主键；
- 时间字段；
- 会显著改变样本或模型含义的高风险特殊值。

## 7. 原始数据、清洗与版本

原始导入数据永远不可变。关联、清洗、变量转换均创建新的数据版本。

建模前诊断和清洗至少覆盖：

- 主键重复、整行重复；
- 数值、文本、日期类型错误；
- 空值、无穷值、特殊编码；
- 极端值和异常分布；
- 类别格式不一致；
- 关联字段格式；
- 同名字段冲突；
- 清洗前后样本量和坏率变化。

不得强制所有模型共享粗暴的统一填补策略。评分卡、逻辑回归和树模型可以使用不同但可追溯的预处理分支。

### 7.1 活动项目本地存储

当前版本采用应用专属本地目录保存活动项目：

- 不自动同步或上传活动项目数据；
- 导入或选择目录时识别常见 iCloud、OneDrive、Dropbox 等同步位置，并给出明确警告；
- 默认不把活动项目直接放入已知云同步目录；
- 本地文件使用操作系统账户权限保护，并建议用户开启 FileVault 或 BitLocker；
- 当前版本不承诺应用层实时加密所有打开中的项目；完整迁移包继续强制加密。

### 7.2 归档与长期保留

已确认当前使用场景以本地个人电脑为主，项目完成后允许长期归档保存，不设置自动删除期限。

归档应具有以下语义：

- 归档项目默认只读，不再占用活动项目和任务列表；
- 默认使用完整归档，原始数据快照、数据字典、Notebook、模型、报告、Trace 和质检记录全部保留；
- 用户可以恢复归档项目并创建新 Run；
- 归档本身不得自动触发外部 LLM 调用或重新训练；
- 删除与归档是两个独立动作，不得把“归档”实现为删除数据；
- 本地长期保存不等于可以忽略安全，敏感字段仍默认脱敏显示，文件完整性继续用哈希校验。

轻量产物归档不作为当前默认流程。完整项目迁移包采用强制密码加密；具体技术参数见后续规格。

### 7.3 删除、回收站与重置

已确认删除采用两阶段机制：

- 普通“删除项目”只将项目移入应用内回收站；
- 回收站中的项目可以恢复；
- 回收站不按 30 天或其他期限自动清理；
- 只有用户主动执行“永久删除”才移除项目数据；
- 永久删除必须输入项目名称进行二次确认；
- 归档、移入回收站和永久删除必须是三个语义明确、视觉上可区分的动作。

系统不得把“归档”或普通“删除”实现为不可恢复的数据清除。SSD 等存储介质上的物理安全擦除能力不得被夸大；具体删除保证应在技术规格和产品文案中如实说明。

设置中心分别提供：

- **只重置设置**：恢复 Provider 以外的普通默认项；密钥删除必须单独确认；
- **删除全部本地项目数据**：列明受影响的项目、归档、回收站和运行记录，二次确认后执行，不与“只重置设置”混用。

删除全部本地项目数据属于高风险动作，必须再次输入确认文字，不得由 Agent 自动触发。

### 7.4 完整项目迁移包

已确认支持将完整项目一键导出为可迁移项目包，并在另一台 macOS 或 Windows 电脑上导入恢复。

项目包包括：

- 原始数据快照和数据字典；
- 数据版本、关联与清洗记录；
- Notebook；
- Y 任务、Run、模型和预处理流水线；
- Web、Excel、HTML 报告；
- Trace、质检记录、配置版本和文件哈希。

迁移包必须满足：

- 采用跨平台格式；
- 完整项目包强制加密，导出时必须设置项目包密码，不提供未加密的完整包；
- 导入时必须使用项目包密码解密；密码不得写入项目包、日志或 Trace；
- 导出时同时允许生成独立恢复密钥，由用户自行保存；
- 不提供厂商云端密码找回，也不把恢复密钥上传到外部服务；
- 密码和恢复密钥任一可用于解密项目包，具体格式和提示必须避免用户误把两者一起丢失；
- 导出前生成 Manifest 和完整性校验；
- 导入时校验包版本、文件哈希和兼容性；
- API Key、系统凭据和本机绝对路径不得进入项目包；
- Provider 配置可以保留非敏感部分，但导入后需要在目标设备重新绑定密钥；
- 导入的 Notebook 和代码不得自动执行，必须先通过本地安全检查；
- 导入恢复应创建明确的数据和项目版本，不静默覆盖同名项目。

跨平台项目包已经确定强制密码加密；具体密码强度、遗忘提示、加密算法和密钥派生参数仍待后续技术规格冻结。

### 7.5 本地备份

- 用户可以随时手动创建完整本地备份；
- 应用升级前自动创建兼容性快照；
- 当前版本不默认运行每日定时备份，也不自动上传到云端；
- 备份位置、占用空间、创建时间和恢复入口必须可见；
- 恢复备份创建新项目版本，不静默覆盖当前活动项目。

## 8. Y 识别、有效样本与多 Y 队列

### 8.1 标签前提

当前版本不负责从还款流水计算 FPD、MOB、CPD 等标签。主样本表中的 Y 已经计算完成。

常见值包括：

- `1`：坏样本；
- `0`：好样本；
- `-1` 或空值：可能代表未表现、未成熟或不可用。

`-1` 和空值的业务含义不能全局猜测。Agent 可以提出“本次 Y 排除 `-1` 和空值”的建议，但必须依据数据字典或用户确认。

一个样本可能对 FPD0 已成熟，但对 FPD7、FPD30 尚未成熟。因此每个 Y 独立形成有效样本集合。

### 8.2 多 Y 建模

同时支持：

- 一次只运行一个 Y；
- 一次勾选多个 Y，加入建模队列。

单选与批量排队都必须是一等入口；默认选择行为仍待界面原型确认。资源有限时依次执行。某个 Y 被阻断，不应阻断其他 Y。

## 9. Train、Test 与 OOT 切分

数据通常没有预先标记 Train、Test、OOT，默认由 Agent 根据时间字段和客户主键提出切分方案。

已确认的默认原则：

- 自动识别并要求确认申请时间或放款时间；
- OOT 使用最新且已经表现成熟的时间段；
- Train、Test 来自更早时间；
- Train 和 Test 按客户主键隔离；
- 比例不写死，根据时间跨度、样本量和坏样本数动态建议；
- 切分前展示各集合时间范围、样本量、好坏样本量和坏率；
- 所有候选模型使用同一冻结切分。

同一客户跨时间多次申请时：

- Train 与 Test 严格客户互斥；
- OOT 优先保留真实未来时间边界，可以包含历史客户的未来订单；
- OOT 同时报告“全部客户”和“纯新客户”表现；
- 显示 OOT 重复客户比例；
- 高级选项允许三个集合客户完全互斥。

OOT 在分箱、调参和模型方案冻结前保持锁定。若用户根据 OOT 结果重新修改分箱或模型，系统必须标记“OOT 已用于调参”，原 OOT 不再具有纯粹最终验证含义。

## 10. 资源策略与运行规模

### 10.1 已知典型规模

- 常见样本量：约 2 万至 3 万行；
- 常见字段量：通常不超过 1000 个。

这些是典型场景，不是产品硬限制。

### 10.2 不写死数据上限

系统不以固定行数、字段数或文件大小作为业务能力上限。系统根据 CPU、可用内存、磁盘、数据类型、关联方式和算法动态生成执行计划。

必须提供资源护栏，避免 8GB 本地电脑卡死或进程失控。

允许的资源策略包括：

- 按列分批计算缺失率、IV、单变量指标；
- 按行分块累计统计；
- 行列混合分块；
- 模型、折数和参数组合顺序执行；
- 低成本粗筛后再运行高成本统计；
- 降低并行度；
- 使用磁盘缓存或外存计算；
- 根据运行环境调整资源预算。

界面显示真实批次和任务进度，不使用虚假百分比。

不得为了资源方便而静默删样本或降低正式统计口径。界面预览可以只展示少量行，但正式指标仍使用完整有效样本。

### 10.3 后台运行与断点恢复

已确认本地长任务采用以下行为：

- 关闭浏览器页面不停止本地任务；
- 关闭桌面窗口且仍有运行任务时，询问“继续后台运行”或“停止并退出”；
- 后台运行时必须有系统托盘、菜单栏或等价入口可以重新打开工作台并查看任务；
- 电脑休眠、关机、进程异常或应用更新前，保存到最近完成的安全节点；
- 重新打开应用后允许从最近安全节点恢复；
- 已完成的数据处理、分箱或候选模型不得无理由从头重跑；
- 如果某个模型不支持训练迭代中间恢复，只重跑该模型，不重跑整个项目；
- 恢复后继续使用同一数据版本、方案版本和随机种子，并记录中断与恢复事件；
- 不得把“节点级恢复”宣传成所有算法都支持训练中间的精确续跑。

### 10.4 桌面通知

桌面通知只用于需要用户行动或任务已经结束的关键事件：

- 需要用户确认；
- 任务被阻断或失败；
- 单个 Y 建模完成；
- 多 Y 队列全部完成；
- 最终质检完成。

普通节点和批次进度只在页面内更新，不频繁触发系统通知。用户可以在设置中心关闭全部通知，或按事件类型分别配置。

### 10.5 应用更新与遥测

应用更新采用用户确认方式：

- 检测到新版本后提醒用户；
- 由用户确认后下载和安装；
- 有任务运行时禁止自动更新；
- 更新前保存安全节点并检查项目兼容性；
- 不把“检测更新”扩展为上传项目内容或运行数据。

使用统计和崩溃报告默认关闭。只有用户主动同意后，才允许发送经过脱敏的运行环境、版本和错误摘要；原始数据、字段值、项目名称、本机路径、Notebook 内容和密钥不得进入遥测。

### 10.6 类别不平衡

已确认不进行好样本欠采样、坏样本过采样或 SMOTE。

- Train、Test、OOT 保留真实样本；
- 资源不足不能通过删除样本解决；
- 支持算法级类别权重；
- 使用权重时记录策略并检查概率校准；
- 最终评价基于真实 Test 和 OOT 分布。

## 11. 变量筛选

### 11.1 筛选漏斗

变量筛选包含：

1. 业务禁用、PII、主键和泄漏字段；
2. 缺失、常量、单一值、高基数等质量问题；
3. IV、单变量 AUC/KS、分箱表现；
4. 变量 PSI 和时间稳定性；
5. 相关性聚类和冗余处理；
6. 逻辑回归的 VIF、系数方向、显著性、正则化或逐步筛选；
7. 树模型的重要性、Permutation Importance、SHAP 等模型专项证据；
8. 最终变量审核。

VIF 主要服务线性模型，不得机械用于淘汰树模型变量。IV 不得作为唯一筛选依据；异常高 IV 需要检查泄漏或高基数虚高。

### 11.2 已确认的参考阈值

以下是用户提供的个人参考值，不是不可调整的行业硬标准：

| 指标 | 默认参考 | 产品语义 |
|---|---:|---|
| 最低 IV | 0.02 | 低于时建议排除或复核 |
| 最大相关系数 | 0.70 | 超过时进入相关性处理，不能简单同时删除 |
| 最大缺失率 | 30% | 超过时进入复核；缺失本身有信息时可保留或单独成箱 |

半信任模式在变量筛选前展示汇总确认卡，用户可以：

- 接受并继续；
- 修改阈值；
- 查看变量详情。

系统必须记录最终阈值、规则版本以及入模变量的选择理由。

### 11.3 人工恢复变量

用户可以恢复被普通筛选规则排除的变量，但必须填写业务原因。恢复后由 Reviewer 重新检查，并使受影响的分箱、训练和报告失效后重跑。

以下字段属于硬阻断，不允许强行恢复为模型特征：

- 姓名、身份证、手机号等直接标识符；
- 明确的数据或标签泄漏字段；
- 在模型决策时间点不可获得的贷后字段；
- 违反字段契约或安全策略的字段。

系统必须区分“用户恢复普通变量”和“绕过安全阻断”，后者不可提供按钮。

## 12. 评分卡变量分箱

逻辑回归评分卡必须支持自动分箱和人工分箱。

### 12.1 自动分箱

- 只使用 Train 拟合分箱；
- 对数值变量进行预分箱并合并相邻区间；
- 对类别变量进行可解释的类别合并；
- 支持缺失值和特殊值独立成箱；
- 控制最小箱样本量、最小好坏样本量和最大箱数；
- 目标是得到业务合理、坏率与 WOE 单调、不过度细分的方案；
- 无法合理单调化时进入人工复核或建议排除。

### 12.2 人工分箱工作区

人工分箱不是小弹窗，而是中间主工作区中的完整页面。用户可以：

- 合并相邻箱；
- 移动数值边界；
- 拆分箱；
- 调整类别组合；
- 处理缺失与特殊值；
- 查看样本量、坏率、WOE、IV 和单调性；
- 撤销、恢复和保存分箱版本。

Reviewer 检查过细分箱、样本不足、过拟合、业务含义和稳定性。

不得为了保留变量或让报告好看而强行修改箱数。一个变量若只有强行压成极少箱才能单调，且 IV 明显下降，Agent 应建议排除。

## 13. 候选模型与调参

### 13.1 候选模型

已确认的候选模型方向：

- WOE + Logistic Scorecard；
- 正则化 Logistic Regression；
- XGBoost；
- LightGBM；
- CatBoost；
- Random Forest / Extra Trees；
- Dummy Baseline，仅作为最低基准，不作为正式模型。

Agent 根据样本、字段类型、缺失、类别不平衡和设备资源推荐组合，不默认把所有模型全部执行。

默认至少推荐一个可解释逻辑回归模型，搭配一至两个效果模型。评分卡逻辑回归默认开启，但允许用户在“建模方案”阶段直接关闭。

### 13.2 模型开关位置

本次候选模型开关放在中间工作区的“建模方案确认”页面，每张模型卡片直接显示“参与本次训练”开关。

不得把本次模型开关藏入设置中心。设置中心只保存未来项目的默认偏好。

页面同时提供：

- 恢复 Agent 推荐组合；
- 添加其他模型；
- 查看推荐理由；
- 确认方案并开始训练。

训练开始后修改候选模型，应创建新 Run 或明确重跑训练阶段，不得静默覆盖原结果。

### 13.3 调参

参数搜索由 Agent 自动完成，并根据设备资源调整搜索范围：

- 只在 Train 内部交叉验证；
- Test 用于候选比较；
- OOT 用于冻结后的最终验证；
- 普通模式隐藏复杂参数；
- 高级模式允许查看和修改参数范围。

## 14. Agent、HITL、Reviewer 与质检

### 14.1 信任模式

新项目默认半信任模式。

半信任模式采用“阶段级集中确认”，而不是对每个细节弹窗。用户可以配置哪些阶段自动执行、哪些阶段必须确认；阻断问题单独处理。

主要确认节点包括：

- 数据关联与样本粒度；
- Y 值、成熟规则和有效样本；
- 清洗方案；
- 变量筛选与分箱；
- Train/Test/OOT 切分；
- 候选模型；
- 最终模型结论。

完全信任模式仍不能绕过数据安全、泄漏、执行安全和最终质检。

### 14.2 Agent 与 Reviewer 闭环

已确认流程：

1. 主 Agent 生成计划或代码；
2. Reviewer 执行独立上下文审核；
3. 本地 Worker 执行通过门禁的确定性任务或受控代码；
4. Reviewer 审核结果、指标和产物一致性；
5. 问题结构化反馈给主 Agent；
6. 主 Agent 修复并重新审核。

最多三轮自动修复。三轮仍未通过时允许一次安全降级，例如减少变量、恢复默认分箱或切换稳定基线；仍失败则停止，不能带问题生成“成功报告”。

### 14.3 训练过程反馈

训练界面至少显示：

- 当前模型；
- 当前交叉验证折数；
- 参数搜索进度；
- 耗时；
- 资源占用；
- Reviewer 状态；
- 修复轮次；
- 当前工具和节点。

默认展示结构化执行摘要，不展示隐藏思维链或大段原始日志。日志与工具参数可以按需展开。

用户可以对 Agent 回复点赞、点踩并补充原因；反馈只评价回复质量，不得代替阶段确认或模型批准。

### 14.4 最终质检

Reviewer Agent 是最终质检把关节点。质检状态采用三级：

- **通过**：可以锁定正式模型、导出正式报告并批量打分；
- **有条件通过**：不存在阻断性错误，但有未解决风险；允许内部验证、批量打分和导出，风险必须跟随模型、报告、产物包和任务记录；在风险关闭前不得标记为“可生产部署”；
- **不通过**：不能形成正式模型，返回修复或停止。

质检至少检查：

- 样本、Y、切分与 OOT 口径；
- 数据与标签泄漏；
- 入模变量、分箱、WOE 和系数一致性；
- Train、Test、OOT 的分箱边界一致性；
- 排序性；
- 页面、Excel、HTML 数值一致性；
- 模型与批量打分可复现性；
- 敏感字段和导出边界。

## 15. 多 Agent 模型配置

首批 Provider 目标：

- DeepSeek；
- Kimi；
- Kimi Code；
- OpenAI API 格式；
- Anthropic API 格式；
- 自定义兼容接口。

设置中心支持多个 Provider 配置、API Key、本地安全存储和连通性测试。

连通性测试、配置保存、Provider 启用和实际 LLM 调用必须是四个可以区分的状态：

- 测试成功只代表当前表单参数可连通，不得让用户误以为已经保存或已经触发 Agent；
- 测试成功后提供明显的“保存并启用”动作；
- 保存启用后说明“从下一次 Agent 调用生效，已经结束或阻断的 Run 不会自动重跑”；
- 顶部 Provider 状态只表达配置是否可用，运行时间线另外展示本次节点是否真的调用了 LLM；
- 实际调用记录展示 Agent、模型、用途、耗时、成功或失败和 Token 用量，不展示原始敏感载荷。

主 Agent 与 Reviewer 默认使用同一个已配置模型，但上下文和提示词独立；高级设置允许 Reviewer 使用不同模型或不同 Provider。

报告必须如实区分：

- 同模型独立 Reviewer；
- 跨模型 Reviewer。

使用同一模型时不得宣传为“不同模型交叉审核”。

## 16. LLM 数据安全边界

原始数据不得上传到外部 LLM。

### 16.1 禁止外发

- 原始数据行；
- 姓名、身份证、手机号；
- 唯一主键；
- 可识别单个样本的值；
- 小样本分组；
- 本机路径；
- API Key 和其他密钥；
- 原始模型文件和逐行预测结果。

### 16.2 允许的 SafeEvidence

- 通过本地 PII 检查后的字段名、字段类型和数据字典说明；敏感字段名必须删除或使用稳定别名；
- 行数、缺失率、唯一值数量；
- Y 聚合分布；
- 样本量达到 30 的分箱或分组统计；不足 30 的分组只标记为“小样本已抑制”，不发送数值；
- IV、KS、AUC、PSI、Lift 等指标；
- 已脱敏代码和错误；
- 本地工具结果的结构化摘要。

SafeEvidence 不得包含原始数据行、样本示例、唯一值、直接标识符或能够反推出单个对象的组合。所有外发内容必须先通过本地 DLP。

已确认采用“项目级确认一次 + 每次调用可审计”的方式，不为每次外部调用重复弹窗。用户可以查看每次调用发送的安全摘要、模型、用途、耗时和结果。

## 17. 模型评价与 Champion 推荐

### 17.1 总体指标

每个候选模型和 Champion 至少展示：

- Train、Test、OOT 的样本量；
- 好样本数、坏样本数和坏样本率；
- AUC；
- KS；
- PR-AUC；
- Train 为基准的 Test/OOT 分数 PSI；
- Train、Test、OOT 的差距与稳定性。

PSI 是数据集之间的相对比较，不得表现为单个数据集的独立指标。

### 17.2 参考线

用户给出的当前个人参考值：

- AUC 参考线：0.55；
- KS 参考线：0.15。

这些是可配置的推荐参考，不是写死的全局硬门槛。

### 17.3 分数分箱与绝对排序性

- 分数越高，风险越低；
- 由 Train 生成固定分数分箱边界；
- Test 和 OOT 使用相同边界；
- 默认以等频 10 箱作为主要展示，20 箱作为补充诊断；
- 分数从低到高时，坏样本率应持续下降；
- Train、Test、OOT 都检查严格单调、倒挂位置、箱样本量和排序相关；
- 不允许通过静默改箱数、重新分箱或合并倒挂箱美化结果；
- 样本不足时标记“无法可靠判断”，不能判定通过。

明显排序倒挂的模型默认不能成为 Champion，除非形成有依据的例外记录。

### 17.4 自动推荐

Agent 自动推荐 Champion，同时保留 Challenger。

推荐不能只按最高 AUC 或 KS，需要综合：

- OOT 表现；
- Train/Test/OOT 差距；
- PSI；
- 分箱排序；
- Lift；
- 概率校准；
- 变量数量；
- 模型复杂度和解释性。

若所有模型均不适合，Agent 必须输出“本次无可推荐模型”，不得强行选择最不差的模型。

### 17.5 概率校准

已确认由 Agent 判断候选模型是否需要概率校准：

- 不对所有模型强制校准；
- 同时保留原始概率与校准结果，不能静默覆盖；
- 校准方案只能使用 Train 内部交叉验证和 Test 证据选择；
- OOT 不得参与校准方法选择或参数拟合；
- 只有在可靠性、稳定性和业务使用上具有明确收益时，才推荐校准版本；
- 报告展示校准前后曲线、误差和对排序指标的影响；
- 最终评分使用原始概率还是校准概率，必须写入模型版本和评分规则。

## 18. 评分卡与评分转换

### 18.1 评分卡与模型文件

- WOE + Logistic Regression 可以生成传统加法评分卡；
- XGBoost、LightGBM、CatBoost、Random Forest 等通常以模型文件加预处理流水线交付；
- 树模型可以把坏概率转换为风险分，但不应冒充传统逐变量加分评分卡。

### 18.2 分数方向与范围

已确认：

- 分数越高代表风险越低；
- 默认分数范围为 300—900；
- 分数范围可以调整；
- 默认基准为：好坏比 `20:1` 时对应 600 分，好坏比每翻一倍增加 50 分，即 PDO 为 50；
- 高级设置支持修改基础分、基础好坏比和 PDO，并同步展示修改后的换算示例。

不得按当前批次的最大、最小概率做 Min-Max 缩放，否则不同批次和模型版本之间的分数不可比较。

## 19. 批量打分

模型确认后支持上传新 CSV、Excel 并执行批量打分。

已确认的默认交付方式：

- 保留原表全部字段和原始行顺序；
- 在原表末尾增加评分列；
- 评分列名默认使用模型名称；
- 模型名称默认建议为 `Y名称_算法名称_版本号`，允许修改；
- 多个模型同时打分时，增加多个对应模型名称列；
- 不静默覆盖同名字段；
- 无法评分的样本单独形成异常样本表。

默认结果不强制增加坏概率、风险等级、原因码或每行质检状态。这些属于可选高级输出。

“有条件通过”的模型允许用于内部验证、批量打分和导出，但其质检状态、限制和模型版本必须记录在任务级说明中，且不得被标记为“可生产部署”。

## 20. 模型报告与导出

报告主要面向懂风控指标的专业用户，同时提供：

- 管理摘要；
- 专业详情。

### 20.1 Excel

导出排版良好的 `.xlsx`，包含三个核心 Sheet：

1. **01_模型总览**
   - 项目、Y、样本和时间；
   - Train/Test/OOT 样本和好坏分布；
   - 候选模型 AUC、KS、PR-AUC、PSI；
   - Champion、Challenger 和 Reviewer 结论；
   - 评分规则和关键图表。
2. **02_变量与分箱**
   - 只展示最终入模变量；
   - 变量含义、来源、缺失、IV、PSI、相关性、重要性；
   - 逻辑回归系数、方向；
   - 变量分箱、样本量、坏率、WOE、IV 贡献。
3. **03_模型分数分箱**
   - Train/Test/OOT 使用同一边界并列展示；
   - 10 箱与 20 箱；
   - 样本量、好坏数、坏率、Lift、累计捕获、KS、PSI 贡献；
   - 排序性和倒挂标记；
   - 分数分布、坏率、Lift 和累计捕获图。

排除变量及理由不进入正式 Excel 第二 Sheet，但继续保存在项目运行记录和审计产物中。

### 20.2 单文件 HTML

- 单个可离线打开的 HTML；
- CSS、JavaScript、图表资源内嵌；
- 不依赖服务器或外部 CDN；
- 支持图表交互、筛选、折叠、Tooltip 和目录跳转；
- 只包含聚合报告，不包含直接标识符或原始数据；
- 可通过浏览器打印为 PDF。

### 20.3 一致性

Web、Excel、HTML 必须使用同一份结构化报告数据，不能分别重新计算指标。

导出入口位于结果报告页面右上角，直接展示“导出 Excel”“导出 HTML”“导出模型产物包”，不得藏在设置中心。

### 20.4 模型产物包

质检状态为“通过”或“有条件通过”后自动生成模型产物包，不要求用户额外点击生成。

模型产物包至少包括：

- 模型文件或评分卡规则；
- 完整预处理流水线；
- 输入字段契约；
- 分箱、WOE 和评分转换规则；
- 可执行 Notebook；
- 依赖与环境清单；
- 模型版本、数据版本、随机种子和配置；
- 最小复现检查和校验哈希；
- Reviewer 与最终质检结论。

模型产物包必须能够脱离交互式 Notebook 独立执行评分，并提供稳定的批量评分入口、输入输出示例和版本锁定。底层模型采用适合对应算法的标准格式，具体格式由技术规格和跨平台兼容性测试决定，不要求业务用户选择。

模型产物包不包含原始训练数据、直接标识符或 API Key。“有条件通过”的剩余风险必须写入包内说明，且包内状态不得标记为“可生产部署”。

## 21. 工作台信息架构

用户已经明确提出的整体结构：

- 左侧：项目列表和新建项目；底部进入设置中心；
- 中间：当前项目和当前建模任务的主工作区；
- 右侧：当前 Run、阶段、Agent、工具、风险和下一步；
- 中间底部：始终展开的项目级 Agent 对话。

中间主区域只保留三个一级视图：

- 当前工作台；
- 产物报告；
- 历史 Run。

数据、清洗、筛选、训练等建模阶段不再作为一排同级顶部 Tab，而由右侧运行阶段和中间当前任务内容共同表达。

右侧运行栏优先展示当前阶段、当前 Agent、当前工具、阻断/警告和下一步动作；完整事件历史默认折叠，按需展开。

底部 Agent 对话默认且持续展开，不采用默认折叠方案。具体高度和是否允许用户拖动调整，留给三版原型比较，但不能通过切换到独立“Agent 对话”Tab 才能使用。

当前任务的开关和确认必须放在对应工作阶段，不得全部塞进设置中心。

设置中心负责全局默认项：Provider、API Key、默认模型、默认信任模式、预算、代理、证书、资源策略等。

以下 UI 细节仍需通过三版原型和用户选择确认：

- 左、中、右栏具体宽度；
- 底部常驻对话的高度与可调整方式；
- 运行状态与模型报告的视觉层级；
- 空项目、无数据、运行中、阻断、完成等关键页面状态。
